


太棒了！为个人搭建一个AI知识库，是真正能提升我们学习、思考和创造效率的“超能力”。它不仅仅是笔记软件，更是你的 **“第二大脑”（Second Brain）的智能版本**。

与企业知识库不同，个人知识库的核心在于 **极低的维护成本、高度的个性化和绝对的隐私**。

以下是为个人搭建AI知识库的全面最佳实践，从理念到工具，再到工作流。

---

### 核心原则：从“归档”思维转向“连接”思维

在开始之前，必须转变一个观念：

*   **旧方法（归档思维）：** 我要把笔记放进哪个文件夹？我该用什么标签？我们像图书管理员一样，小心翼翼地分类。
*   **新方法（AI连接思维）：** **我只需要把信息“扔”进去，然后通过提问和AI来发现它们之间的联系。** 系统的智能性远比你的分类能力重要。

记住，你的目标不是建立一个完美的目录，而是建立一个能与你“对话”并激发新想法的伙伴。

---

### 阶段一：选择你的平台（三大路径）

选择合适的平台是第一步，也是最关键的一步。这取决于你的技术能力、预算和对隐私的重视程度。

#### 路径1：一体化、零代码方案（适合大多数人）

这些是集成了AI功能的成熟笔记软件，开箱即用。

*   **推荐首选：Obsidian [<sup>1</sup>](https://obsidian.md/) + 插件**
    *   **为什么是最佳实践？** 它是 **本地优先 (Local-First)** 的典范。你的所有笔记都以纯文本Markdown文件的形式存在你的电脑上，你拥有100%的数据所有权和隐私。
    *   **如何实现AI？** 通过社区插件。安装 `Smart Connections` 或 `Copilot` 插件，它就能让你在本地与你的所有笔记进行对话和查询。
    *   **优点：** 绝对隐私、数据可控、免费（核心功能）、社区庞大、插件生态极度丰富。
    *   **缺点：** AI功能需要自己安装插件并进行简单配置（例如填入OpenAI API Key）。

*   **其他选择：Notion AI [<sup>2</sup>](https://www.notion.so/product/ai)**
    *   **优点：** AI功能无缝集成，用户体验极其顺滑，非常适合团队协作。
    *   **缺点：** **非本地存储**。你的所有数据都在Notion的云端，对于非常私密的想法或日记，需要慎重考虑。有月度订阅费。

#### 路径2：半DIY方案（适合注重隐私的极客）

使用本地大语言模型（LLM）应用，完全在你的电脑上运行AI，不向任何云端发送数据。

*   **推荐工具：AnythingLLM [<sup>3</sup>](https.anythingllm.com/) / LM Studio [<sup>4</sup>](https://lmstudio.ai/)**
    *   **工作原理：** 你下载一个开源大模型（如Llama 3, Qwen），然后在这些软件里指定一个存放你所有笔记/文档的文件夹。软件会自动处理嵌入和索引，让你能与这些本地文档对话。
    *   **优点：** **极致的隐私和安全**，无持续费用，完全离线可用。
    *   **缺点：** 对你的电脑硬件有一定要求（建议至少有8GB VRAM的显卡），需要一些初始设置，AI模型的性能可能不及GPT-4。

#### 路径3：完全DIY方案（适合开发者）

如果你是开发者，可以从零开始构建自己的系统。

*   **技术栈：**
    *   **向量数据库：** `ChromaDB` / `FAISS`
    *   **嵌入模型：** 从Hugging Face下载开源模型
    *   **前端界面：** `Streamlit` / `Gradio`
*   **优点：** 完全的控制权和定制化。
*   **缺点：** 非常耗时，维护成本高。

---

### 阶段二：内容策略（喂给AI吃什么？）

工具只是一个空壳，内容才是灵魂。

1.  **统一格式为王：Markdown (. md)**
    *   **最佳实践：** 无论你从哪里收集信息，都尽量将其转换为Markdown格式。这是最通用、最持久、最易于被各种工具处理的格式。
    *   **工具：**
        *   **网页剪藏：** 使用Obsidian或Notion的官方剪藏插件，一键保存文章为Markdown。
        *   **PDF/图片：** Obsidian的 `Text Extractor` 插件可以自动读取PDF和图片中的文字。
        *   **格式转换：** 使用 `Pandoc` 等工具进行批量转换。

2.  **建立“捕捉一切”的习惯**
    *   **原则：** 如果某个信息未来可能对你有用，或者你希望你的“第二大脑”知道它，就把它捕捉进来。不要预判，不要过度分类。
    *   **捕捉内容示例：**
        *   **阅读笔记：** 书籍、文章、论文的摘要和思考。
        *   ** fleeting Notes：** 随时冒出的灵感、想法、待办事项。
        *   **会议纪要：** 关键决策和行动项。
        *   **代码片段和技术解决方案。**
        *   **个人日记和反思。**
        *   **项目计划和研究资料。**

3.  **少量元数据，而非大量标签 (Light Metadata)**
    *   **最佳实践：** 不要陷入“标签地狱”。AI的强大之处在于理解内容本身，而非依赖你的标签。
    *   你只需要在笔记开头用模板加入最基础的元数据即可，例如：
        ```markdown
        ---
        source: "https://example.com/article"
        author: "John Doe"
        creation_date: 2024-08-01
        ---
        ```
    *   AI可以利用这些元数据进行更精确的回答，例如“帮我找一下John Doe写过的，关于AI的文章”。

---

### 阶段三：日常工作流（如何使用？）

1.  **让捕捉“无摩擦”**
    *   利用手机的“分享”菜单、电脑的快捷键，将捕捉信息的步骤减到最少。一旦有了想法，必须能在5秒内将其记录下来。

2.  **学会“提问”，而非“搜索”**
    *   这是使用AI知识库的核心。改变你的思维方式：
        *   **旧搜索：** 输入关键词 "时间管理番茄工作法"
        *   **新提问：** "我所有笔记里，关于如何提高专注力的方法有哪些？把它们总结成一个列表。"
        *   **旧搜索：** "AI 伦理"
        *   **新提问：** "把我之前读过的关于AI伦理的几篇文章的核心论点进行对比，它们之间有什么矛盾之处？"

3.  **利用AI进行“思想碰撞”**
    *   当你学习一个新概念时，可以问你的知识库：
        > "我正在学习‘系统思维’，这个概念和我笔记库里的哪些其他主题有关联？"
    *   AI可能会帮你发现“系统思维”与你之前记录的“项目管理”、“生态学”甚至“个人健康”笔记之间的惊人联系。

4.  **定期“花园打理”（Weekly Review）**
    *   每周花30分钟回顾一下本周捕捉的笔记。
    *   **目的：**
        *   为一些零散的笔记补充上下文。
        *   修正AI可能误解的内容。
        *   将一些笔记与现有项目关联起来。
        *   删除明显无用的垃圾信息。
    *   这能确保你的知识库信噪比越来越高，成为一个值得信赖的伙伴。

### 总结：推荐的“新手最佳实践套装”

如果你想立刻开始，这是一个平衡了易用性、功能和隐私的最佳组合：

1.  **核心软件：** **Obsidian**
2.  **AI插件：** **Smart Connections**
3.  **核心工作流：**
    *   **捕捉：** 使用Obsidian Web Clipper和手机应用，将所有有价值的信息保存到Obsidian的“收件箱”(Inbox) 文件夹。
    *   **提问：** 打开Smart Connections面板，直接用自然语言与你的整个知识库对话。
    *   **整理：** 每周花点时间，将“收件箱”里的笔记稍微整理，或链接到相关的笔记上。

通过这套实践，你将能建立一个真正属于你、能与你共同成长、并能极大增强你认知能力的个人AI知识库。




# 重排
当然！这是一个极佳的问题，因为它触及了现代AI系统中一个非常关键但常被忽视的“优化层”。

简单来说，**重排模型 (Reranker)** 就像一个 **“精品筛选官”** 或 **“复试面试官”**。

在很多AI系统中，我们通常会分两步走：
1.  **第一步（海选/召回 - Recall）**：用一个快速、成本低的方法，从海量数据中（比如数百万份文档）先捞出一批可能相关的候选者（比如100个）。这个阶段要求“快”和“全”，宁可错杀一千，不可放过一个。
2.  **第二步（复试/重排 - Rerank）**：用一个更强大、更精准但计算成本更高的模型（也就是重排模型），对这100个候选者进行精细打分和排序，选出最终的“冠军”或Top-K结果。这个阶段要求“准”。

所以，你的问题“哪些也能用重排模型？”可以理解为：**“在哪些场景下，这种先‘海选’再‘复试’的两阶段策略是有效的？”**

以下是几个最典型和最有效的应用场景：

---

### 1. 知识库/企业内部搜索引擎

这是重排模型最经典、效果最显著的应用场景。

*   **没有重排模型之前：**
    员工搜索“公司今年的报销政策有什么变化？”，系统通过关键词匹配或基本的向量搜索，可能会返回所有包含“报销”、“政策”、“变化”的文档。结果列表里可能混杂着去年的旧政策、某个部门的讨论草案、甚至是不相关的IT系统变更通知。
*   **加入重排模型之后：**
    重排模型会逐一判断“查询”与这批返回文档之间的 **真实语义相关性**。它能理解“今年的”、“变化”这些词的深层含义，从而将 **最新发布的官方正式文件** 排在最前面，而将过时的、非官方的文档排在后面。这极大地提升了搜索结果的精准度。

### 2. RAG (检索增强生成) 系统

在当前最火的RAG应用中，重排模型是提升最终生成答案质量的“秘密武器”。

*   **没有重排模型之前：**
    当用户提问时，RAG系统从知识库中检索出N个相关的文本片段（chunks），然后把这些片段一股脑地塞给大语言模型（LLM），让它去总结回答。如果检索出的片段质量不高，含有噪声或矛盾信息，LLM生成的答案也会变得混乱或不准确（“垃圾进，垃圾出”）。
*   **加入重排模型之后：**
    在将文本片段送给LLM之前，重排模型会先对这些片段进行一次“精选”。它会筛选出与用户问题 **最相关、信息量最足、最关键** 的几个片段。
    *   **好处1：** 提高了答案的准确性，减少了LLM产生幻觉的概率。
    *   **好处2：** 减少了送入LLM的上下文长度，节省了Token成本和计算时间。

### 3. 电商网站的商品搜索

电商搜索不仅要相关，更要懂用户的“潜在意图”。

*   **没有重排模型之前：**
    用户搜索“适合新手的跑鞋”。传统搜索引擎可能会返回所有标题里包含“新手”和“跑鞋”的商品。
*   **加入重排模型之后：**
    重排模型可以被训练来理解更复杂的概念。它知道“适合新手”通常意味着 **更好的缓冲、支撑性、保护性**，而不是追求极致轻量或碳板性能。因此，它会把那些具有这些特性的跑鞋排在前面，即使它们的商品标题里没有明确写出“新手”二字。此外，它还可以结合商品的 **好评率、销量、品牌声誉** 等信息进行综合排序。

### 4. 推荐系统（如新闻、视频推荐）

推荐系统的目标是在用户有限的注意力里，展示他们最可能感兴趣的内容。

*   **没有重排模型之前：**
    一个初步的推荐模型（如协同过滤）可能会生成一个包含100个视频的候选列表。
*   **加入重排模型之后：**
    重排模型可以对这个列表进行“上下文感知”的优化。例如，它会考虑：
    *   **多样性：** 避免推荐的10个视频都是同一类型，造成用户审美疲劳。
    *   **新鲜度：** 将刚刚发布的热点内容排在前面。
    *   **用户序列行为：** 如果用户刚刚看完一个“篮球教学”视频，那么下一个推荐“篮球比赛集锦”的权重就应该被提高。

### 5. 智能问答（QA）系统

在需要从多个候选答案中挑选最佳答案的场景中，重排模型也大有可为。

*   **场景：** 系统针对一个问题，从不同来源或用不同方法生成了多个候选答案。
*   **加入重排模型之后：**
    重排模型可以评估 **“问题”和每一个“候选答案”** 之间的匹配度、流畅度和可信度，从而选出最优质的答案呈现给用户。

---

### 总结：一张图看懂

| 应用场景 | 初步候选者 (海选) | 重排模型的目标 (复试) |
| :--- | :--- | :--- |
| **知识库搜索** | 包含关键词或向量相似的文档 | 找出 **语义最相关、最权威** 的官方文档 |
| **RAG系统** | 可能包含答案的文本片段 | 筛选出 **最关键、噪声最少** 的片段喂给LLM |
| **电商搜索** | 标题或标签匹配的商品 | 结合 **用户潜在意图和商品属性** 综合排序 |
| **推荐系统** | 基于用户历史行为的推荐列表 | 优化列表的 **多样性、新鲜度和上下文相关性** |
| **智能问答** | 多个可能的候选答案 | 选出 **最准确、最流畅、最可信** 的一个答案 |

总而言之，只要你的系统里存在一个 **“从一个较大候选集合中，筛选出少数最佳结果”** 的环节，那么引入重排模型（Reranker）来充当“精品筛选官”，都是一个非常值得考虑的优化方向。



# 1 实现
好的，这正切中了当前AI应用发展的一大趋势！通过低代码/无代码（Low-code/No-code）平台，即使没有深厚的编程背景，也能轻松地搭建和部署一个包含重排模型的先进AI知识库。

这些平台将复杂的技术（如向量数据库、嵌入模型、重排器）封装成了可视化的“模块”或“节点”，你只需要像搭积木一样将它们拖拽、连接、并填写一些配置即可。

下面，我将以最主流的开源低代码AI应用搭建平台 **Flowise** 为例，为你提供一个详细的、手把手的实现指南。

### 核心理念：从写代码到“画流程图”

传统的代码实现，你需要关心库的安装、函数的调用顺序、API的异步处理等。

低代码平台则将这个过程变成了一个可视化的流程图：

**`[加载文档] -> [文本切分] -> [向量化] -> [存入向量库] -> [配置重排器] -> [连接大模型] -> [输出答案]`**

### 实战演练：使用 Flowise 搭建带重排功能的知识库

Flowise 是一个开源项目，可以轻松地在本地或服务器上通过 Docker 运行。

**前提准备：**

1.  **安装 Flowise:** 在你的电脑上安装 Docker，然后打开终端（命令行工具），运行以下命令：
    ```bash
    docker run -d --name flowise -p 3000:3000 -v ~/.flowise:/root/.flowise flowiseai/flowise
    ```
    等待片刻，然后在浏览器中打开 `http://localhost:3000` 即可看到Flowise的界面。

2.  **准备API密钥：**
    *   **OpenAI API Key**: 用于文档的“向量化”和最终的“问答生成”。
    *   **Cohere API Key**: 用于“重排模型”。Cohere提供非常慷慨的免费额度，非常适合初学者。访问 Cohere官网 [<sup>1</sup>](https://cohere.com/) 注册即可获取。

---

**手把手搭建步骤：**

我们将搭建一个能回答“Flowise 是什么？”的知识库。

#### 第1步：创建新的聊天流程 (Chatflow)

在Flowise主界面，点击 “Add New” 创建一个新的空白画布。

#### 第2步：搭建基础的RAG流程（不含重排）

我们先搭一个基础版，让你感受一下流程，然后再把“重排器”这个超级武器加进去。

1.  **加载文档 (Loader):**
    *   点击左侧的 `+ Add Node` 按钮。
    *   在 `Loaders` -> `Text File` 中，选择 `Text File` 节点。
    *   在节点配置里，上传一个 `flowise_intro.txt` 文件，内容为：“Flowise是一个开源的低代码工具，用于构建定制化的大语言模型应用。它通过可视化的界面，让用户可以拖拽组件来搭建复杂的AI流程。”

2.  **切分文本 (Text Splitter):**
    *   `+ Add Node` -> `Text Splitters` -> `Recursive Character Text Splitter`。
    *   将 `Text File` 节点的输出点（右侧的小圆点）拖拽连接到 `Recursive...Splitter` 节点的输入点上。

3.  **向量化和存储 (Embedding & Vector Store):**
    *   `+ Add Node` -> `Embeddings` -> `OpenAI Embeddings`。
    *   在弹出的 `Credentials` 对话框中，选择 `Create New` 并填入你的 `OpenAI API Key`。
    *   `+ Add Node` -> `Vector Stores` -> `In-Memory Vector Store` (这是最简单的一种，无需配置数据库)。
    *   **连接它们！** 将 `Recursive...Splitter` 连接到 `In-Memory Vector Store` 的 `Document` 输入上；将 `OpenAI Embeddings` 连接到 `In-Memory Vector Store` 的 `Embeddings` 输入上。

4.  **创建问答链 (Chain):**
    *   `+ Add Node` -> `Chains` -> `Conversational Retrieval QA Chain`。
    *   将 `In-Memory Vector Store` 连接到 `Conversational...Chain` 的 `Vector Store Retriever` 输入上。
    *   `+ Add Node` -> `Chat Models` -> `ChatOpenAI`。将它连接到 `Conversational...Chain` 的 `Chat Model` 输入上。同样，配置好你的 `OpenAI API Key`。

现在，保存你的流程。点击右上角的紫色对话气泡按钮，你可以开始测试了。这就是一个 **基础的RAG系统**。



#### 第3步：注入“重排模型”！(关键步骤)

现在我们来升级！

1.  **断开连接:** 先删除 `In-Memory Vector Store` 和 `Conversational...Chain` 之间的连接线。我们需要在中间插入重排器。

2.  ==**添加重排检索器 (Retrieval with Reranker):**==
    *   `+ Add Node` -> `Retrievers` -> `Contextual Compression Retriever`。这正是LangChain中集成重排器的官方组件。
    *   **配置它！**
        *   **Base Retriever**: 将 `In-Memory Vector Store` 连接到这个输入上。这告诉它：“你的海选数据从这里来”。
        *   **Base Compressor**: 这是配置重排模型的入口。
            *   `+ Add Node` -> `Document Compressors` -> `Cohere Rerank`。
            *   在弹出的 `Credentials` 中，创建并填入你的 `Cohere API Key`。
            *   在 `Cohere Rerank` 节点的 `Top N` 配置中，可以填入 `3`。这表示：“无论海选出多少篇，请帮我精选出最相关的3篇”。
            *   将 `Cohere Rerank` 节点连接到 `Contextual Compression Retriever` 的 `Base Compressor` 输入上。

3.  **重新连接问答链:**
    *   现在，将 `Contextual Compression Retriever` 节点的输出，连接到我们之前创建的 `Conversational Retrieval QA Chain` 的 `Vector Store Retriever` 输入上。

# 2
好的，使用 n8n 来实现一个带重排功能的 RAG 流程是一个非常棒的实践！这比在 Flowise 或 Dify 上需要更多的手动配置，但它提供了无与伦比的灵活性和对数据流的控制力。

n8n 是一个通用的工作流自动化工具，而不是专门的 LLM 应用构建器。因此，我们没有现成的“Cohere Rerank”节点，但这完全没问题——我们可以通过其强大的 `HTTP Request` 节点来调用任何 API。

下面，我将为你提供一个完整、详细的指南，一步步教你如何在 n8n 中从零开始构建这个高级 RAG 系统。

### 核心架构

我们将把整个流程分为两个独立的 n8n 工作流：

1.  **工作流 #1 : 文档索引 (一次性运行)**
    *   **目标:** 读取源文档（例如一个PDF），切分它，创建向量嵌入，并将其存入向量数据库（我们将使用 Pinecone 作为例子）。
    *   **流程:** `读取PDF` -> `切分文本` -> `调用OpenAI API创建嵌入` -> `存入Pinecone`

2.  **工作流 #2 : 问答与重排 (实时运行)**
    *   **目标:** 接收用户问题，查询向量库，用Cohere重排结果，最后用LLM生成答案。
    *   **流程:** `Webhook触发` -> `创建问题嵌入` -> `查询Pinecone` -> **`调用Cohere API重排`** -> `构建上下文` -> `调用OpenAI API生成回答` -> `返回答案`

### 前提准备

1.  **n8n 实例:** 确保你有一个正在运行的 n8n 服务（本地 Docker 或云端）。
2.  **API 密钥:**
    *   **OpenAI API Key:** 用于创建文本嵌入和最终的问答。
    *   **Cohere API Key:** 用于调用重排模型。
    *   **Pinecone API Key:** 用于存储和检索向量。访问 Pinecone 官网注册一个免费账户，并创建一个 Index（例如，命名为 `n8n-rag`，==维度设为 `1536` 以匹配 OpenAI 的 `text-embedding-ada-002` 模型）。==

---

### 第一步：构建“文档索引”工作流

这个工作流只需在你有新文档时运行一次。

1.  **节点 1: Manual Trigger (手动触发)**
    *   添加一个 `Schedule` 节点，并将其设置为 `At none of the specified times`，这实际上让它变成了一个可以手动点击 "Execute Workflow" 运行的节点。

2.  **节点 2: Read PDF (读取PDF)**
    *   `+` -> `Read PDF`。
    *   在配置中，上传你想要索引的PDF文件。

3.  **节点 3: Edit Fields (提取文本)**
    *   `+` -> `Edit Fields`。
    *   这个节点用来从PDF节点复杂的输出中只提取我们需要的文本内容。
    *   在 "Fields" 部分，设置一个新字段，例如 `text`，其值设置为表达式 `{{ $json.text }}`。这会把前一个节点的文本内容放到一个叫做 `text` 的干净字段里。

4.  **节点 4: Split in Batches (切分文本)**
    *   `+` -> `Split in Batches`。
    *   **Batch Size**: 设置为 `1`。
    *   **Options -> Batching**:
        *   **Mode**: 选择 `Split A Field Containing Text`。
        *   **Field to Split**: 填写 `text` (我们在上一步创建的字段)。
        *   **Chunk Size**: `1000` (每块1000个字符)。
        *   **Chunk Overlap**: `200` (块之间的重叠字符数)。

5.  **节点 5: HTTP Request (创建 OpenAI 嵌入)**
    *   `+` -> `HTTP Request`。
    *   **Request Method**: `POST`
    *   **URL**: `https://api.openai.com/v1/embeddings`
    *   **Authentication**: `Header Auth`。
    *   **Name**: `Authorization`
    *   **Value**: `Bearer sk-YOUR_OPENAI_API_KEY` (替换成你的密钥)。
    *   **Body Content Type**: `JSON`
    *   **Body**:
        ```json
        {
          "input": "{{ $json.text }}",
          "model": "text-embedding-ada-002"
        }
        ```
    *   这个节点会为每一个文本块调用一次 OpenAI API，并返回向量。

6.  **节点 6: Pinecone (存入向量库)**
    *   `+` -> `Pinecone`。
    *   **Pinecone API**: `Create New`，填入你的 Pinecone 密钥和环境。
    *   **Operation**: `Upsert`。
    *   **Index**: 选择你之前创建的索引 (e.g., `n8n-rag`)。
    *   **Vector**: 使用表达式 `{{ $json.data[0].embedding }}` 从 `HTTP Request` 节点的输出中提取向量。
    *   **Metadata Fields**: `Fields to Add: text`。点击 `Add Field`，`Name` 设为 `text`，`Value` 设为 `{{ $('Split in Batches').item.json.text }}`。 **这非常重要**，它将原始文本和向量关联起来，以便我们之后能找回原文。

**完成！** 点击 "Execute Workflow"，你的PDF就会被处理并存入Pinecone了。

---

### 第二步：构建“问答与重排”工作流

这是将实时回答用户问题的核心流程。

1.  **节点 1: Webhook (触发器)**
    *   `+` -> `Webhook`。它会自动生成一个URL。你可以用这个URL来触发工作流。在测试时，n8n会提供一个测试URL。

2.  **节点 2: HTTP Request (创建问题嵌入)**
    *   这是一个和索引流程中几乎一样的 `HTTP Request` 节点。你可以直接从上一个工作流复制粘贴过来。
    *   **唯一的区别** 是 Body 中的 `input` 字段。它需要从 Webhook 中获取用户的问题。
    *   **Body**:
        ```json
        {
          "input": "{{ $json.query.question }}", 
          "model": "text-embedding-ada-002"
        }
        ```
        *(假设用户通过 `.../webhook?question=你的问题` 的方式提问)*

3.  **节点 3: Pinecone (查询相似文档)**
    *   `+` -> `Pinecone`。
    *   **Operation**: `Query`。
    *   **Index**: 选择同一个索引。
    *   **Vector**: 使用表达式 `{{ $json.data[0].embedding }}` 从上一步获取问题的向量。
    *   **Top K**: `10`。这代表“海选”，我们先找出10个可能相关的文档。

4.  **节点 4: HTTP Request (调用 Cohere Rerank - 关键步骤!)**
    *   `+` -> `HTTP Request`。
    *   **Request Method**: `POST`
    *   **URL**: `https://api.cohere.com/v1/rerank`
    *   **Authentication**: `Header Auth`。
    *   **Name**: `Authorization`
    *   **Value**: `Bearer YOUR_COHERE_API_KEY` (替换成你的密钥)。
    *   **Body Content Type**: `JSON`
    *   **Body** (这里需要用一点表达式技巧):
        ```json
        {
          "model": "rerank-english-v2.0",
          "query": "{{ $('Webhook').item.json.query.question }}",
          "documents": {{ $json.matches.map(match => match.metadata.text) }},
          "top_n": 3
        }
        ```
    *   **解释**:
        *   `query`: 我们从最初的 Webhook 节点获取用户的问题。
        *   `documents`: 这是最巧妙的部分。我们使用 `map` 函数遍历前一个 Pinecone 节点返回的10个结果 (`$json.matches`)，并只提取其中的元数据文本 (`match.metadata.text`)，形成一个文本列表。
        *   `top_n`: `3`，我们告诉 Cohere：“请从这10个文档中，帮我精选出最相关的3个”。

5.  **节点 5: Code (构建最终上下文)**
    *   `+` -> `Code` (运行JavaScript代码)。
    *   Cohere的返回结果只告诉了我们新的排序，我们需要根据这个排序来整理原始文档。
    *   **JavaScript Code**:
        ```javascript
        const rerankedResults = $json.results; // 来自Cohere Rerank节点的结果
        const originalDocs = $('Pinecone').item.json.matches; // 来自Pinecone查询的原始文档

        let finalContext = "";
        for (const result of rerankedResults) {
          const originalDoc = originalDocs[result.index];
          finalContext += originalDoc.metadata.text + "\n\n";
        }

        // 返回一个包含干净上下文的对象
        return [{ finalContext: finalContext }];
        ```

6.  **节点 6: OpenAI (生成答案)**
    *   `+` -> `OpenAI` -> `Chat`。
    *   **Mode**: `Chat`。
    *   在 `Messages` 部分:
        *   **Role**: `System`
        *   **Content**: `You are a helpful assistant. Answer the user's question based on the following context. If the context does not contain the answer, say so.\n\nContext:\n{{ $('Code').item.json.finalContext }}`
        *   点击 `Add Message Item`:
        *   **Role**: `User`
        *   **Content**: `{{ $('Webhook').item.json.query.question }}`

7.  **节点 7: Respond to Webhook (返回答案)**
    *   `+` -> `Respond to Webhook`。
    *   **Respond With**: `First Entry of another Node`。
    *   **Source Node**: `OpenAI`。
    *   **Response Data**: `Selected fields from JSON`。
    *   **Fields to Include**: `choices`。

现在，**激活你的工作流**！你可以通过浏览器访问你的 Webhook URL (例如 `.../webhook-test/123?question=flowise是什么`)，稍等片刻，就能看到由重排模型优化过的、由LLM生成的精准答案了。
