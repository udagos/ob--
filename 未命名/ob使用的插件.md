#### ==Auto Link Title==

  

- **功能**：自动获取网页标题，生成带标题的 Markdown 链接。
  
- **安装**：通过 Obsidian 社区插件页面搜索“Auto Link Title”，安装并启用。
  
- **基本使用**：粘贴 URL 时，插件自动获取标题，生成如 [标题](URL) 的链接。Windows 用 Ctrl+Shift+E，Mac 用 Cmd+Shift+E 增强已有链接。
  
- **高级功能**：  
    - 支持 LinkPreview API，需设置 API 密钥以获取更详细的标题和描述。
      
    - 从 1.5.5 版起，支持使用不可见字符保持粘贴占位符整洁，需在设置中启用。
      
    
  
- **注意事项**：部分 URL 或上下文可能不完美，需测试；确保 API 密钥正确配置。
  

#### ==Auto Note Mover==

  

- **功能**：根据规则自动移动笔记至指定文件夹。
  
- **安装**：通过社区插件安装，启用后进入设置。
  
- **基本使用**：设置标签（如 #tag）或标题（用 JavaScript 正则表达式）匹配规则，自动移动笔记。
  
- **触发方式**：自动（新建、编辑、重命名时）或手动（通过命令面板）。
  
- **高级功能**：  
    - 支持嵌套标签和每日笔记规则。
      
    - 若目标文件夹不存在，可自动创建；文件名冲突时显示警告。
      
    - 前置元数据“AutoNoteMover: disable”可禁用特定笔记的自动移动。
      
    
  
- **注意事项**：附件文件不随笔记移动，需注意同步软件（如 Dropbox）可能干扰，详见 [GitHub Issue #19](https://github.com/farux/obsidian-auto-note-mover/issues/19)。
  

#### AutoTemplateTrigger

  

- **功能**：新建文件时自动应用模板。
  
- **安装**：安装后需确保核心“Templates”插件已启用，设置模板文件夹。
  
- **基本使用**：新建文件时，若只有一个模板自动应用，多个模板弹出选择框。
  
- **文件夹关联**：可为特定文件夹分配模板，优先级按最具体路径计算。
  
- **高级功能**：  
    - 禁用提示选项强制使用文件夹模板，无选择框。
      
    - 支持嵌套文件夹模板，适合复杂结构。
      
    
  
- **注意事项**：需确保模板文件存在，否则功能受限。

#### ==BetterCommand Palette==

- **安装**：安装后启用，设置中可调整快捷键。

- **高级功能**：  
    - 最近使用命令优先显示，支持固定命令。
      
    - 支持宏命令，设置中定义多步操作，延迟可调。
      
    - 隐藏项管理，可临时或永久显示，快捷键 Cmd+I 查看。

#### ==Chronology==

  

- **功能**：显示笔记创建和修改时间线。
  
- **安装**：安装后启用，插件自动显示时间线。
  
- **基本使用**：点击月份查看该月所有笔记，Ctrl+点击在新窗格打开。
  
- **导航与显示**：  
    - 支持日、周、月或自定义范围选择，Shift+点击选定范围。
      
    - 启用“Display Simple List”显示列表视图，“Group Notes in same time slot”分组时间线。
      
    
  
- **高级功能**：1.1.9 版支持从文件元数据读取创建日期，解决 Obsidian Sync 问题。
  
- **注意事项**：需注意性能，复杂时间线可能影响编辑流畅度。

在 JavaScript 中，可以使用 `JSON.parse()` 方法将 JSON 字符串转换为 JavaScript 对象。以下是具体的步骤和示例：

### 1. 使用 `JSON.parse()` 方法
`JSON.parse()` 是一个内置的 JavaScript 方法，用于将 JSON 格式的字符串解析为 JavaScript 对象。

#### 示例代码：
```javascript
// JSON 字符串
const jsonString = '{"name":"Kimi","age":23,"isDeveloper":true}';

// 使用 JSON.parse() 转换为 JavaScript 对象
const jsonObject = JSON.parse(jsonString);

console.log(jsonObject);
// 输出：{ name: 'Kimi', age: 23, isDeveloper: true }

console.log(jsonObject.name); // 输出：Kimi
console.log(jsonObject.age);  // 输出：23
console.log(jsonObject.isDeveloper); // 输出：true
```

### 2. 注意事项
- **确保 JSON 格式正确**：如果 JSON 字符串格式不正确（例如缺少引号、括号不匹配等），`JSON.parse()` 会抛出语法错误（`SyntaxError`）。例如：
  ```javascript
  const invalidJson = '{"name":Kimi,"age":23}'; // 键值对的值没有引号
  const obj = JSON.parse(invalidJson); // 会抛出 SyntaxError
  ```
- **处理异常**：为了避免程序因错误的 JSON 格式而崩溃，可以使用 `try...catch` 块来捕获错误：
  ```javascript
  const jsonString = '{"name":Kimi,"age":23}'; // 错误的 JSON 格式

  try {
    const obj = JSON.parse(jsonString);
    console.log(obj);
  } catch (error) {
    console.error("JSON 格式错误：", error.message);
  }
  ```

### 3. 反向操作
如果你需要将 JavaScript 对象转换为 JSON 字符串，可以使用 `JSON.stringify()` 方法。例如：
```javascript
const obj = { name: "Kimi", age: 23, isDeveloper: true };
const jsonString = JSON.stringify(obj);

console.log(jsonString);
// 输出：{"name":"Kimi","age":23,"isDeveloper":true}
```

### 总结
- 使用 `JSON.parse()` 将 JSON 字符串转换为 JavaScript 对象。
- 使用 `JSON.stringify()` 将 JavaScript 对象转换为 JSON 字符串。
- 注意 JSON 格式的正确性，并使用 `try...catch` 捕获可能的错误。

TypeScript（TS）和 JavaScript（JS）是两种密切相关但又有所区别的编程语言。TypeScript 是 JavaScript 的一个超集，它在 JavaScript 的基础上添加了类型系统和其他一些特性，以帮助开发者更好地构建大型、复杂的项目。以下是 TypeScript 和 JavaScript 的主要区别：

---

### **1. 类型系统**

这是 TypeScript 和 JavaScript 最显著的区别。

#### **JavaScript**

- JavaScript 是一种**动态类型语言**，这意味着变量的类型是在运行时决定的，而不是在编写代码时指定的。
    
- 变量可以随时改变类型：
    
    JavaScript复制
    
    ```javascript
    let x = 10;       // x 是数字类型
    x = "Hello";      // x 现在是字符串类型
    x = true;         // x 现在是布尔类型
    ```
    
- 动态类型语言的优点是灵活性高，但缺点是容易出现类型相关的错误，尤其是在大型项目中。
    

#### **TypeScript**

- TypeScript 是一种**静态类型语言**，它在 JavaScript 的基础上添加了类型系统。
    
- 在 TypeScript 中，变量的类型在编写代码时需要明确指定（或通过类型推断自动确定）：
    
    TypeScript复制
    
    ```typescript
    let x: number = 10;   // x 是数字类型
    x = 20;               // 可以重新赋值为数字
    // x = "Hello";       // 错误：类型不匹配
    ```
    
- 静态类型系统的主要优点是可以在编译阶段（而不是运行时）捕获类型错误，减少运行时错误，提高代码的可维护性和可读性。
    

---

### **2. 编译过程**

#### **JavaScript**

- JavaScript 是一种**解释型语言**，通常由浏览器或 Node.js 环境直接运行。
    
- 源代码不需要编译，直接在运行时执行。
    

#### **TypeScript**

- TypeScript 是一种**编译型语言**，它需要先将代码编译成 JavaScript，然后才能运行。
    
- TypeScript 编译器（`tsc`）会检查代码中的类型错误，并将 TypeScript 代码转换为 JavaScript 代码。
    
- 例如：
    
    TypeScript复制
    
    ```typescript
    // TypeScript 文件 (example.ts)
    let x: string = "Hello";
    console.log(x);
    ```
    
    编译后：
    
    JavaScript复制
    
    ```javascript
    // 编译后的 JavaScript 文件 (example.js)
    let x = "Hello";
    console.log(x);
    ```
    

---

### **3. 语法和特性**

#### **JavaScript**

- JavaScript 是一种功能强大的语言，支持面向对象编程（OOP）、函数式编程（FP）等多种编程范式。
    
- 它的语法相对灵活，但也容易导致一些常见的错误（如类型错误、拼写错误等）。
    

#### **TypeScript**

- TypeScript 在 JavaScript 的基础上添加了许多新特性，这些特性主要围绕类型系统展开：
    
    - **类型注解**：可以为变量、函数参数和返回值指定类型。
        
        TypeScript复制
        
        ```typescript
        function add(a: number, b: number): number {
          return a + b;
        }
        ```
        
    - **接口（Interfaces）**：用于定义对象的结构。
        
        TypeScript复制
        
        ```typescript
        interface Person {
          name: string;
          age: number;
        }
        
        let person: Person = { name: "Alice", age: 30 };
        ```
        
    - **类和继承**：TypeScript 提供了更严格的类型检查和访问修饰符（如 `public`、`private`、`protected`）。
        
        TypeScript复制
        
        ```typescript
        class Animal {
          protected name: string;
        
          constructor(name: string) {
            this.name = name;
          }
        }
        
        class Dog extends Animal {
          bark() {
            console.log(`${this.name} says woof!`);
          }
        }
        ```
        
    - **泛型**：允许开发者定义可复用的类型。
        
        TypeScript复制
        
        ```typescript
        function identity<T>(arg: T): T {
          return arg;
        }
        
        let output = identity<string>("Hello");
        ```
        

---

### **4. 工具和生态系统**

#### **JavaScript**

- JavaScript 的生态系统非常庞大，有大量的库和框架（如 React、Vue、Node.js 等）。
    
- 它是 Web 开发的核心语言，几乎所有的浏览器都支持 JavaScript。
    

#### **TypeScript**

- TypeScript 的生态系统相对较小，但正在迅速增长。
    
- 它主要用于大型项目和需要严格类型检查的场景。
    
- 许多现代框架（如 Angular）默认支持 TypeScript，而其他框架（如 React 和 Vue）也提供了对 TypeScript 的良好支持。
    

---

### **5. 性能**

#### **JavaScript**

- JavaScript 的性能直接取决于运行环境（如浏览器或 Node.js）的 JavaScript 引擎。
    
- 由于不需要编译，代码的加载和执行速度通常更快。
    

#### **TypeScript**

- TypeScript 代码需要先编译为 JavaScript，因此在运行时会有一些额外的开销。
    
- 然而，编译过程通常可以在开发阶段完成，对最终用户的性能影响较小。
    

---

### **总结：何时使用 TypeScript，何时使用 JavaScript？**

- **使用 TypeScript 的场景**：
    
    - **大型项目**：TypeScript 的类型系统可以帮助团队更好地管理代码，减少错误。
        
    - **需要严格类型检查**：TypeScript 的类型系统可以提前发现潜在的错误，提高代码质量。
        
    - **使用现代框架**：许多现代框架（如 Angular）默认使用 TypeScript，或者提供了对 TypeScript 的良好支持。
        
- **使用 JavaScript 的场景**：
    
    - **小型项目或快速开发**：JavaScript 的灵活性更适合快速开发和小型项目。
        
    - **不需要类型检查**：如果项目对类型检查的需求不高，JavaScript 可能是一个更简单、更轻量级的选择。
        

---

总的来说，TypeScript 是 JavaScript 的一个超集，它在 JavaScript 的基础上提供了类型系统和其他高级特性，帮助开发者更好地构建大型、复杂的项目。如果你需要更严格的类型检查和更好的代码维护性，TypeScript 是一个不错的选择；如果你更注重灵活性和开发速度，JavaScript 仍然是一个强大的工具。
