在多线程编程中，递归持有信号量（Semaphore）可能导致死锁。为了避免这种情况，可以使用计数信号量（Counting Semaphore），它允许多个线程同时访问共享资源，只要信号量的值大于0。计数信号量的值表示可用资源的数量，每次获取信号量时，值减1；每次释放信号量时，值加1。

以下是一个使用计数信号量避免递归持有导致死锁的示例。

### 示例：使用计数信号量避免递归持有导致的死锁

假设我们有一个线程，它需要多次递归调用一个函数，每次调用都需要获取一个信号量。**如果信号量的初始值足够大，可以避免死锁。**

#### 定义信号量
```c
#include <rtthread.h>

rt_sem_t sem;
```

#### 初始化信号量
```c
void init_semaphore(void)
{
    // 初始化信号量，初始值为10，表示可以同时允许10个线程持有该信号量
    sem = rt_sem_create("sem", 10, RT_IPC_FLAG_FIFO);
    if (sem == RT_NULL)
    {
        rt_kprintf("Failed to create semaphore\n");
    }
}
```

#### 递归函数
```c
void recursive_function(int depth)
{
    if (depth > 0)
    {
        // 请求信号量
        rt_sem_take(sem, RT_WAITING_FOREVER);

        // 递归调用
        recursive_function(depth - 1);

        // 释放信号量
        rt_sem_release(sem);
    }
}
```

#### 主函数
```c
int main(void)
{
    init_semaphore();

    // 调用递归函数，深度为5
    recursive_function(5);

    return 0;
}
```

### 代码解析

1. **初始化信号量**
   - 使用 `rt_sem_create` **创建一个计数信号量，初始值为10。这意味着最多可以有10个线程同时持有该信号量。**
   - 如果信号量创建失败，打印错误信息。

2. **递归函数**
   - 在每次递归调用中，调用 `rt_sem_take` 获取信号量。
   - 递归调用自身，深度减1。
   - 在递归调用返回后，调用 `rt_sem_release` 释放信号量。

3. **主函数**
   - 调用 `init_semaphore` 初始化信号量。
   - **调用 `recursive_function`，深度为5**。

### 避免死锁的方法

1. **使用计数信号量**：计数信号量允许多个线程同时访问共享资源，只要信号量的值大于0。通过设置足够的初始值，可以避免递归调用中的死锁。
2. **设置合理的初始值**：根据递归调用的最大深度设置信号量的初始值。例如，**如果递归调用的最大深度为5，信号量的初始值应至少为5。**

### 总结

通过使用计数信号量并设置合理的初始值，可以有效避免递归调用中因多次持有信号量而导致的死锁问题。计数信号量的值表示可用资源的数量，每次获取信号量时，值减1；每次释放信号量时，值加1。这种方法适用于需要多次递归调用的场景，确保线程安全和程序的正确性。
