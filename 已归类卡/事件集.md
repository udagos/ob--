# rt_event_send

这段代码是 RT-Thread 操作系统中事件（Event）发送函数 `rt_event_send` 的实现。它的主要功能是向事件对象发送一个事件集，并唤醒等待该事件的线程。以下是对这段代码的详细解析和解释。

### 功能描述
- **发送事件**：向事件对象发送一个事件集。
- **唤醒等待的线程**：如果有线程因等待该事件而挂起，根据线程的等待条件（AND 或 OR）唤醒这些线程。
- **触发调度**：如果恢复了线程，触发调度器重新调度线程。

### 参数
- `event`：指向事件对象的指针。
- `set`：要发送的事件集。

### 返回值
- `RT_EOK`：操作成功。
- `-RT_ERROR`：操作失败，例如发送的事件集为空。

### 代码解析

#### 参数检查
```c
RT_ASSERT(event != RT_NULL);
if (set == 0)
    return -RT_ERROR;
```
- 检查事件对象是否为 `NULL`。
- 检查发送的事件集是否为空，如果为空，返回 `-RT_ERROR`。

#### 调用对象释放钩子
```c
RT_OBJECT_HOOK_CALL(rt_object_put_hook, (&(event->parent.parent)));
```
- 调用对象释放钩子函数，允许用户在发送事件时执行自定义逻辑。

#### 禁用中断
```c
level = rt_hw_interrupt_disable();
```
- 禁用中断，保护临界区，确保事件操作的原子性。

#### 设置事件
```c
event->set |= set;
```
- 将发送的事件集与事件对象的当前事件集进行位或操作，更新事件对象的事件集。

#### 检查是否有线程挂起
```c
if (!rt_list_isempty(&event->parent.suspend_thread))
{
    /* search thread list to resume thread */
    n = event->parent.suspend_thread.next;
    while (n != &(event->parent.suspend_thread))
    {
        /* get thread */
        thread = rt_list_entry(n, struct rt_thread, tlist);

        status = -RT_ERROR;
        if (thread->event_info & RT_EVENT_FLAG_AND)
        {
            if ((thread->event_set & event->set) == thread->event_set)
            {
                /* received an AND event */
                status = RT_EOK;
            }
        }
        else if (thread->event_info & RT_EVENT_FLAG_OR)
        {
            if (thread->event_set & event->set)
            {
                /* save recieved event set */
                thread->event_set = thread->event_set & event->set;

                /* received an OR event */
                status = RT_EOK;
            }
        }

        /* move node to the next */
        n = n->next;

        /* condition is satisfied, resume thread */
        if (status == RT_EOK)
        {
            /* clear event */
            if (thread->event_info & RT_EVENT_FLAG_CLEAR)
                event->set &= ~thread->event_set;

            /* resume thread, and thread list breaks out */
            rt_thread_resume(thread);

            /* need do a scheduling */
            need_schedule = RT_TRUE;
        }
    }
}
```
- 检查是否有线程因等待该事件而挂起。
- 遍历挂起线程列表，检查每个线程的等待条件是否满足。
	- 如果线程的等待条件是 `AND`，检查发送的事件集是否包含线程等待的所有事件。
	- 如果线程的等待条件是 `OR`，检查发送的事件集是否包含线程等待的任意一个事件。
- 如果条件满足，恢复线程，并设置 `need_schedule` 为 `RT_TRUE`。
- 如果线程的等待条件包含 `RT_EVENT_FLAG_CLEAR`，清除事件对象中已接收的事件。

#### 启用中断
```c
rt_hw_interrupt_enable(level);
```
- 启用中断，结束临界区保护。

#### 触发调度
```c
if (need_schedule == RT_TRUE)
    rt_schedule();
```
- 如果恢复了线程，调用 `rt_schedule` 触发调度器，重新调度线程。

#### 返回值
```c
return RT_EOK;
```
- 返回 `RT_EOK`，表示操作成功。

### 总结

`rt_event_send` 函数的主要功能是向事件对象发送一个事件集，并根据线程的等待条件唤醒等待该事件的线程。它通过以下步骤实现：
1. 检查参数和事件对象的有效性。
2. 禁用中断，保护临界区。
3. 更新事件对象的事件集。
4. 遍历挂起线程列表，检查每个线程的等待条件是否满足。
5. 如果条件满足，恢复线程，并设置需要重新调度。
6. 启用中断，结束临界区保护。
7. 如果恢复了线程，触发调度器重新调度线程。
8. 返回操作结果。

这个函数确保了事件操作的原子性和正确性，同时提供了灵活性，允许用户在发送事件时执行自定义逻辑。



# rt_event_recv
这段代码是 RT-Thread 操作系统中事件（Event）接收函数 `rt_event_recv` 的实现。它的主要功能是接收事件对象中的事件，并根据指定的选项和超时时间等待事件的发生。以下是对这段代码的详细解析和解释。

### 功能描述
- **接收事件**：从事件对象中接收指定的事件集。
- **等待事件**：如果事件尚未发生，根据指定的选项（AND 或 OR）和超时时间等待事件的发生。
- **处理超时**：如果指定了超时时间，等待超时后返回超时错误。
- **清除事件**：如果指定了清除选项，接收后清除事件对象中的相应事件。

### 参数
- `event`：指向事件对象的指针。
- `set`：要接收的事件集。
- `option`：接收选项，可以是 `RT_EVENT_FLAG_AND` 或 `RT_EVENT_FLAG_OR`。
- `timeout`：等待超时时间，单位为毫秒。如果为0，表示不等待；如果为 `RT_WAITING_FOREVER`，表示无限等待。
- `recved`：用于存储接收到的事件集的指针。

### 返回值
- `RT_EOK`：操作成功。
- `-RT_ERROR`：操作失败，例如参数无效。
- `-RT_ETIMEOUT`：等待超时。

### 代码解析

#### 参数检查
```c
RT_ASSERT(event != RT_NULL);
if (set == 0)
    return -RT_ERROR;
```
- 检查事件对象是否为 `NULL`。
- 检查要接收的事件集是否为空，如果为空，返回 `-RT_ERROR`。

#### 初始化状态
```c
status = -RT_ERROR;
thread = rt_thread_self();
thread->error = RT_EOK;
```
- 初始化状态变量 `status` 为 `-RT_ERROR`。
- 获取当前线程指针 `thread`。
- 重置当前线程的错误状态为 `RT_EOK`。

#### 调用对象尝试获取钩子
```c
RT_OBJECT_HOOK_CALL(rt_object_trytake_hook, (&(event->parent.parent)));
```
- 调用对象尝试获取钩子函数，允许用户在尝试获取事件时执行自定义逻辑。

#### 禁用中断
```c
level = rt_hw_interrupt_disable();
```
- 禁用中断，保护临界区，确保事件操作的原子性。

#### 检查事件集
```c
if (option & RT_EVENT_FLAG_AND)
{
    if ((event->set & set) == set)
        status = RT_EOK;
}
else if (option & RT_EVENT_FLAG_OR)
{
    if (event->set & set)
        status = RT_EOK;
}
else
{
    RT_ASSERT(0);
}
```
- 根据选项检查事件集：
	- 如果选项是 `RT_EVENT_FLAG_AND`，检查事件对象的事件集是否包含所有指定的事件。
	- 如果选项是 `RT_EVENT_FLAG_OR`，检查事件对象的事件集是否包含任意一个指定的事件。
- 如果既不是 `RT_EVENT_FLAG_AND` 也不是 `RT_EVENT_FLAG_OR`，断言失败。

#### 处理事件接收
```c
if (status == RT_EOK)
{
    *recved = (event->set & set);

    if (option & RT_EVENT_FLAG_CLEAR)
        event->set &= ~set;
}
else if (timeout == 0)
{
    thread->error = -RT_ETIMEOUT;
}
else
{
    thread->event_set = set;
    thread->event_info = option;

    rt_ipc_list_suspend(&(event->parent.suspend_thread), thread, event->parent.parent.flag);

    if (timeout > 0)
    {
        rt_timer_control(&(thread->thread_timer), RT_TIMER_CTRL_SET_TIME, &timeout);
        rt_timer_start(&(thread->thread_timer));
    }

    rt_hw_interrupt_enable(level);

    rt_schedule();

    if (thread->error != RT_EOK)
        return thread->error;

    level = rt_hw_interrupt_disable();

    *recved = thread->event_set;
}
```
- 如果事件已经满足条件：
	- 设置接收到的事件集。
	- 如果指定了清除选项，清除事件对象中的相应事件。
- 如果超时时间为0，设置线程错误为 `-RT_ETIMEOUT`。
- 否则：
	- 填充线程的事件信息。
	- 将线程挂起到事件对象的挂起线程列表中。
	- 如果指定了超时时间，启动线程定时器。
	- 启用中断并触发调度器。
	- 如果线程错误不是 `RT_EOK`，返回线程错误。
	- 禁用中断并设置接收到的事件集。

#### 启用中断
```c
rt_hw_interrupt_enable(level);
```
- 启用中断，结束临界区保护。

#### 调用对象获取钩子
```c
RT_OBJECT_HOOK_CALL(rt_object_take_hook, (&(event->parent.parent)));
```
- 调用对象获取钩子函数，允许用户在获取事件后执行自定义逻辑。

#### 返回值
```c
return thread->error;
```
- 返回线程的错误状态。

### 总结

`rt_event_recv` 函数的主要功能是接收事件对象中的事件，并根据指定的选项和超时时间等待事件的发生。它通过以下步骤实现：
1. 检查参数和事件对象的有效性。
2. 禁用中断，保护临界区。
3. 根据选项检查事件集是否满足条件。
4. 如果事件已经满足条件，设置接收到的事件集并清除事件。
5. 如果事件尚未满足条件且指定了超时时间，将线程挂起并启动定时器。
6. 启用中断并触发调度器。
7. 如果线程错误不是 `RT_EOK`，返回线程错误。
8. 返回操作结果。

这个函数确保了事件接收操作的原子性和正确性，同时提供了灵活性，允许用户在接收事件时执行自定义逻辑。
