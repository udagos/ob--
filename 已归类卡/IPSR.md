**IPSR 在异常处理过程中的作用**

当发生异常时，ARM Cortex-M 处理器的异常处理流程中，IPSR 起着关键作用：

1. **异常检测和触发：** 当 CPU 检测到异常事件发生 (例如，接收到中断请求，发生 Fault 错误)，会触发异常处理过程。
    
2. **状态保存 (Stacking)：** CPU 会自动将当前程序的状态 (包括 PC, PSR, 寄存器等) 压入堆栈 (Stack)。 **在压栈的过程中，当前的 PSR 值 (包括 IPSR) 也会被保存到堆栈中。** 这样在异常处理程序返回后，可以恢复原来的程序状态。
    
3. **进入异常处理程序：**
    
    - **查找异常向量：** CPU 根据发生的异常的 **异常号**，在 **异常向量表 (Vector Table)** 中查找对应的 **异常处理程序的入口地址**。
    - **更新 IPSR：** **CPU 会更新 IPSR 寄存器的 ISR_NUMBER 字段，将它设置为当前正在处理的异常的异常号。** 这表明处理器现在正在执行一个异常处理程序。
    - **跳转到异常处理程序入口地址：** CPU 跳转到从异常向量表获得的异常处理程序入口地址，开始执行异常处理程序代码。
4. **异常处理程序执行：** 在异常处理程序 (ISR) 中，开发者需要编写代码来处理发生的异常事件 (例如，处理中断请求，清除错误标志等)。 **在 ISR 中，可以通过读取 IPSR 寄存器来获取当前 ISR 的异常号 (ISR_NUMBER)。 但这通常在 ISR 内部不是特别常见的操作，更常见的用途是在调试时查看 IPSR 值。**
    
5. **异常返回 (Exception Return)：** 当异常处理程序执行完毕后，通常会执行 **异常返回指令 (例如，`BX LR` 或 `MOVS PC, LR`，且 LR 的值已被设置为异常返回地址)**。 异常返回指令会触发以下动作：
    
    - **从堆栈中恢复状态 (Unstacking)：** CPU 从堆栈中弹出之前保存的程序状态 (包括 PC, PSR, 寄存器等)。 **恢复的 PSR 值中包含了之前保存的 IPSR 值。**
    - **退出异常处理：** CPU 恢复到之前被中断的用户代码执行流程。 **IPSR 寄存器的 ISR_NUMBER 字段会被更新为 0 (如果返回到非异常状态) 或 更新为新的异常号 (如果嵌套了异常)。**
