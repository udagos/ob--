# 向量表

你列出的这两段代码虽然都出现在**ARM启动文件（startup. s）**中，但它们是**完全不同的机制**，分别用于**ARM模式**和**Cortex-M模式**。下面我来给你**对比说明**：

---

### ✅ 第一段（你最初发的）：
```asm
system_vectors:
    ldr pc, _vector_reset
    ldr pc, _vector_undef
    ldr pc, _vector_swi
    ldr pc, _vector_pabt
    ldr pc, _vector_dabt
    ldr pc, _vector_resv
    ldr pc, _vector_irq
    ldr pc, _vector_fiq
```

#### 📌 适用架构：
- **ARM7/ARM9/ARM11**（传统ARM内核）
- **ARM模式（非Cortex-M）**

#### 📌 特点：
- 这是**异常向量表（Exception Vector Table）**
- 地址固定（通常是0x00000000）
- ==每条指令是一个跳转（`ldr pc, xxx`）==
- 需要==通过 `_vector_xxx` 标签定义实际处理函数地址==

---

### ✅ 第二段（你后来发的）：
```asm
__Vectors
    DCD __initial_sp        ; Top of Stack
    DCD Reset_Handler       ; Reset Handler
    DCD NMI_Handler         ; NMI Handler
    DCD HardFault_Handler   ; Hard Fault Handler
    DCD MemManage_Handler   ; MPU Fault Handler
    DCD BusFault_Handler    ; Bus Fault Handler
    DCD UsageFault_Handler  ; Usage Fault Handler
```

#### 📌 适用架构：
- **Cortex-M 系列**（如 M0/M3/M4/M7）

#### 📌 特点：
- ==这是**向量表（Vector Table）**，但**不是指令**，而是**地址表**==
- ==第一项是**栈顶指针初始值**==
- ==第二项是**Reset入口地址**==
- ==后面是各个异常向量的**函数地址**==
- ==由**硬件自动加载**到PC（而不是通过 `ldr` 跳转）==

---

### ✅ 总结对比表：

| 特性       | 第一段（ARM模式）           | 第二段（Cortex-M模式）            |
| -------- | -------------------- | -------------------------- |
| 架构       | ARM7/9/11            | Cortex-M0/M3/M4/M7         |
| 向量表内容    | 是指令（如 `ldr pc, xxx`） | 是地址（如 `DCD Reset_Handler`） |
| 是否包含栈初始值 | ❌ 不包含                | ✅ 第一项是栈顶地址                 |
| 是否自动跳转   | ❌ 需要手动跳转             | ✅ 异常发生时硬件自动跳转到对应地址         |
| 地址       | 通常是0x00000000        | 通常是0x00000000（可通过VTOR重映射）  |

---

### ✅ 一句话总结：
- **第一段是“老ARM”的异常跳转指令表**；
- **第二段是“Cortex-M”的异常地址表（更像一个函数指针数组）**。

你可以根据你用的芯片型号来判断是哪一类。



---
ARM **Cortex-A9（ARMv7-A 架构）** 和 Cortex-A7 一样，**采用传统 ARM 异常向量表机制**，即：

### ✅ 关键点总结：

| 项目               | Cortex-A9（ARMv7-A） |
|--------------------|----------------------|
| 向量表类型         | **指令表（跳转指令）** |
| 是否含栈指针       | ❌ 不含（由启动代码设置） |
| 是否自动跳转       | ✅ 异常发生时自动跳转到对应指令 |

---

### ❗注意：
Cortex-A9 **不**使用 Cortex-M 那种 `DCD` 地址表（即 `DCD __initial_sp`, `DCD Reset_Handler` 那种形式）。  
那是 **Cortex-M 系列（如 M3/M4/M7）的专属机制**，而 Cortex-A9 属于 **应用处理器（Application Processor）**，走的是传统 ARM 异常向量表路径。
## cotexm Rt-Thread中断工作机制
R==T-Thread 在 Cortex-M 内核上的中断工作机制主要依赖于 Cortex-M 的 NVIC==（嵌套向量中断控制器），所有中断通过中断向量表处理：当触发中断时，处理器直接跳转到中断向量表中对应的固定位置执行中断服务程序，中断服务程序地址需设置到 NVIC 的中断向量偏移寄存器中。

RT-Thread 的中断处理过程分为三个阶段：
1. **中断前导程序**：保存 CPU 中断现场，通知内核进入中断状态（`rt_interrupt_enter()` 增加中断嵌套计数） 。
2. **用户中断服务程序**：处理中断，必要时调用 `rt_hw_context_switch_interrupt()` 触发 PendSV 异常进行线程切换（Cortex-M 架构下使用 PendSV 异常辅助上下文切换） 。
3. **中断后续程序**：通知内核离开中断状态（`rt_interrupt_leave()` 减少中断嵌套计数） 。

RT-Thread 采用独立的中断栈，支持中断嵌套（高优先级中断可抢占低优先级中断），且中断服务程序工作在特权级处理模式，优先级高于任何线程。用户只需定义中断服务函数并使其与中断向量表中的中断向量关联即可，无需额外使用 RT-Thread 提供的函数（中断屏蔽与使能除外） [^6]。
## cotexa Rt-Thread中断工作机制
在 **Cortex-A 架构** 下，RT-Thread 的中断工作机制与 Cortex-M 有显著差异，主要体现在异常向量表结构、上下文保存方式、中断栈使用以及线程切换机制等方面。以下是其核心机制详解：

---

### ✅ 1. 中断入口与异常向量表

==Cortex-A 使用 **异常向量表（Exception Vector Table）** 来处理中断，而非 NVIC==。中断触发后，**CPU 自动完成以下操作**：

- 切换到 **IRQ 模式**（或 FIQ 模式）；
- 自动保存 CPSR、PC、LR 等关键寄存器到当前模式的栈中；
- 跳转到异常向量表中对应的中断入口地址（如 `vector_irq`）。

---

### ✅ 2. 中断处理流程（三阶段）

RT-Thread 将中断处理分为以下三个阶段：

| 阶段                | 描述                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **中断前导程序**        | 保存被打断线程的上下文（寄存器、栈指针等），调用 `rt_interrupt_enter()` 增加中断嵌套计数。                                                                 |
| **用户中断服务程序（ISR）** | 执行用户注册的中断处理函数。若需线程切换，则调用 `rt_hw_context_switch_interrupt()` 设置切换标志，**不立即切换**，仅标记待切换线程。                                    |
| **中断后续程序**        | 调用 `rt_interrupt_leave()` 减少嵌套计数，检查是否需要线程切换。若标志置位，则通过 `rt_hw_context_switch_interrupt_do()` 完成上下文切换。线程切换在中断退出后由 SVC 模式完成。 |

---

### ✅ 3. 上下文切换机制

==Cortex-A 不支持像 Cortex-M 那样的自动压栈机制，上下文保存与恢复需手动完成：==

- **保存阶段**：将 r0-r12、lr、spsr 等寄存器压入被打断线程的栈中；
- **恢复阶段**：从目标线程的 TCB 中取出栈指针，恢复寄存器并跳转到新线程执行。

---

### ✅ 4. 中断栈设计

RT-Thread 在 Cortex-A 上采用 **独立中断栈**：

- 中断发生时，切换至系统预留的中断栈；
- 避免中断处理占用线程栈空间，提升内存利用率；
- 支持中断嵌套（高优先级中断可打断低优先级中断）。

---

### ✅ 5. 中断嵌套与优先级

- ==Cortex-A 支持中断嵌套，但需手动配置 GIC==（Generic Interrupt Controller）；
- RT-Thread 通过 `rt_interrupt_nest` 计数中断嵌套层数；
- 线程切换只在**所有中断处理完成后**才触发，避免在中断上下文中直接切换。

---

### ✅ 总结流程图（简化）

```
IRQ触发
   ↓
CPU保存部分寄存器 → 跳转到 vector_irq
   ↓
切换至 SVC 模式 → 保存完整线程上下文 → 调用 ISR
   ↓
ISR 中设置切换标志 → 中断返回前检查
   ↓
若需切换 → 调用 rt_hw_context_switch_interrupt_do → 恢复新线程上下文 → 继续执行
```

---

如需在 Cortex-A 上注册中断，需通过 RT-Thread 的 `rt_hw_interrupt_install()` 接口将 ISR 绑定到对应中断号，并配置 GIC 中断优先级与触发方式。
