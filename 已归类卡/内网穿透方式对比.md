好的，除了 frp、ngrok 和 cpolar 这些广为人知的工具外，内网穿透领域还有许多优秀的选择。它们可以大致分为两类：**基于隧道的转发工具**和**基于虚拟局域网（VPN）的组网工具**。

以下是一些主流的内网穿透工具及其详细对比，希望能帮助您根据需求做出选择。

### 一、 主流内网穿透工具介绍

#### 1. 基于隧道的转发工具 (端口转发)

这类工具的核心是将内网的某个端口映射到公网服务器的一个端口上，实现点对点的穿透。

- **frp:**
    
    - **简介:** 一个非常流行的高性能、开源反向代理工具。功能强大，配置灵活，需要用户自己拥有一台公网服务器。
        
    - **优点:**
        
        - **功能极其丰富:** 支持TCP, UDP, HTTP, HTTPS等多种协议，支持自定义域名、负载均衡、认证、加密、压缩等高级功能。
            
        - **性能高:** 使用Go语言开发，性能出色，资源占用低。
            
        - **开源免费:** 完全开源，可以自由部署和修改。
            
        - **社区活跃:** 拥有庞大的用户社区，文档和教程非常丰富。
            
    - **缺点:**
        
        - **需要自己有公网服务器:** 这是使用frp的前提。
            
        - **配置相对复杂:** 功能强大也意味着配置文件相对复杂，新手需要一定的学习成本。
            
- **ngrok:**
    
    - **简介:** 内网穿透领域的“鼻祖”级工具，非常成熟和稳定，提供了官方的公网服务，开箱即用。
        
    - **优点:**
        
        - **极其易用:** 无需公网服务器，只需下载客户端，一条命令即可启动穿透。
            
        - **功能完善:** 提供了Web UI界面，可以实时查看和回放HTTP请求，非常适合开发调试。
            
        - **稳定可靠:** 作为商业化运营的服务，其公共节点的稳定性和速度有保障。
            
    - **缺点:**
        
        - **免费版限制多:** 免费版提供的域名是随机的、速度受限、连接数有限，且会在一段时间后断开。
            
        - **价格较高:** 专业版和企业版订阅费用相对昂贵。
            
        - **非开源:** 核心服务不开源，无法自由定制和私有化部署（尽管有1.x版本的开源代码，但已过时）。
            
- **cpolar:**
    
    - **简介:** 一款对标ngrok的国产工具，同样提供稳定易用的公网服务，对国内用户非常友好。
        
    - **优点:**
        
        - **易用性强:** 和ngrok类似，无需公网服务器，下载即用，配置简单。
            
        - **国内线路优化:** 服务器在国内，访问速度快，稳定性好。
            
        - **免费版功能更实用:** 免费版提供随机的二级域名，但通常是长期保留的，不会像ngrok那样频繁变动。
            
        - **支持永久隧道:** 可以创建长期稳定的数据隧道，适合个人NAS、远程桌面等场景。
            
    - **缺点:**
        
        - **非开源:** 同样是商业软件，无法私有化部署。
            
        - **免费版带宽有限:** 免费套餐的带宽有限制，更高需求需要付费。
            
- **NPS (Nat Penetration Server):**
    
    - **简介:** 一款功能与frp类似的国产开源内网穿透工具，主打易用性，提供了Web UI管理界面。
        
    - **优点:**
        
        - **Web UI管理:** 可以通过网页轻松完成大部分配置和客户端管理，降低了使用门槛。
            
        - **功能全面:** 支持多协议，支持域名解析、SSL证书等功能，与frp类似。
            
        - **开源免费:** 同样可以自由部署。
            
    - **缺点:**
        
        - **需要自己有公网服务器:** 和frp一样是前提条件。
            
        - **社区和生态:** 相较于frp，社区规模和文档丰富度略逊一筹。
            

#### 2. 基于虚拟局域网的组网工具 (异地组网)

这类工具不是简单地暴露一个端口，而是在多个设备之间创建一个加密的虚拟局域网，让它们好像在同一个路由器下一样，可以通过内网IP直接互相访问。

- **ZeroTier:**
    
    - **简介:** 一款非常强大的“软件定义广域网”（SD-WAN）工具，通过P2P技术和官方根服务器（Planet）进行协调，创建虚拟网络。
        
    - **优点:**
        
        - **配置极其简单:** 无需公网服务器，只需在各设备安装客户端并加入同一个虚拟网络ID即可。
            
        - **P2P直连:** 在大多数网络环境下，设备间可以建立P2P直接连接，延迟低，速度快，不消耗服务器中转流量。
            
        - **安全性高:** 端到端加密，安全性有保障。
            
        - **跨平台支持:** 支持Windows, macOS, Linux, iOS, Android, NAS等几乎所有平台。
            
    - **缺点:**
        
        - **国内P2P成功率:** 在复杂的国内网络环境下，P2P打洞可能失败，此时会通过官方服务器（Moon）中继，速度会变慢。可以自建Moon节点解决。
            
        - **免费版设备限制:** 免费版支持25个设备连接，对于个人和小型团队完全够用。
            
- **Tailscale:**
    
    - **简介:** 基于先进的WireGuard协议构建的虚拟组网工具，以极致的简单和安全著称。
        
    - **优点:**
        
        - **极致简单:** 使用Google、Microsoft、GitHub等现有账号登录即可，无需注册，真正实现“零配置”。
            
        - **安全性极高:** 基于WireGuard，被认为是目前最先进、最安全的VPN协议之一。
            
        - **性能出色:** WireGuard协议本身性能就非常高，连接速度快。
            
        - **P2P直连:** 与ZeroTier类似，尽可能尝试P2P直连。
            
    - **缺点:**
        
        - **依赖第三方认证:** 必须通过指定的身份提供商登录，对某些用户可能不便。
            
        - **免费版限制:** 免费版支持1个用户和20台设备，对个人用户非常友好。

### 三、 如何选择？

- **如果你是开发者，需要临时调试本地程序：**
    
    - **首选 `ngrok` 或 `cpolar`**。它们无需任何配置，一条命令就能解决问题，并且有请求回放功能，是调试利器。
        
- **如果你有自己的公网服务器，并追求高性能和完全的控制权：**
    
    - **首选 `frp`**。它的功能最为强大，可以满足几乎所有复杂的端口转发需求。如果觉得`frp`配置麻烦，可以尝试带Web界面的 **`nps`**。
        
- **如果你想远程访问家里的NAS、电脑，或者和朋友联机打游戏：**
    
    - **首选 `ZeroTier` 或 `Tailscale`**。它们能让你安全、方便地访问整个设备，而不是仅仅一个端口。配置简单，体验如同在同一个局域网内，而且P2P直连能带来更低延迟和更快速度。`Tailscale`因其更简单的认证方式和WireGuard协议，近年来更受欢迎。
        
- **如果你是普通用户，想稳定地把家里的服务（如NAS、网站）发布出去：**
    
    - **付费版的 `cpolar`** 是个不错的选择，因为它有国内优化的线路。如果不想付费，且有一定动手能力，那么用自己的服务器搭建 **`frp`** 是更经济和长久的选择。



# ngrok 或cpolar 有没有长久公网域名的 方法
当然有。为 `ngrok` 或 `cpolar` 获取一个长久固定的公网域名是它们的核心付费功能之一，也是区分免费版和付费版的主要标志。下面为您详细解析两种工具的实现方法以及更优的替代方案。

### 总结先行

|方案|固定域名类型|成本|易用性|推荐场景|
|---|---|---|---|---|
|**cpolar (免费版)**|**固定的二级子域名**<br>(`xxx.cpolar.cn`)|**免费**|高|个人开发者、需要一个稳定免费地址的轻度用户|
|**cpolar (付费版)**|**自定义个人域名**<br>(`dev.yourdomain.com`)|低|高|希望使用自己域名，且追求国内访问速度的用户|

### 一、 cpolar：提供免费的固定子域名

cpolar 在这一点上对免费用户非常友好，是其相对于 ngrok 的一个巨大优势。

#### 1. 免费方案：保留固定子域名（已经不可以了要付费）

cpolar 的免费套餐允许用户通过后台设置，**免费保留一个固定的二级子域名**。虽然这个域名的前缀是系统生成的，但它不会像 ngrok 的免费域名那样在每次重启后都改变。

**操作步骤：**

1. **登录 cpolar 官网后台：** 访问 [cpolar.com](https://www.cpolar.com/) 并登录。
    
2. **进入“预留”菜单：** 在左侧仪表盘找到“预留”选项。
    
3. **保留一个固定地址：** 在这里你可以看到你的隧道信息。找到“保留的TCP地址”或类似的选项，可以为你的隧道保留一个固定的 `subdomain.cpolar.cn` 地址和端口。
    
4. **在本地使用保留的隧道：** 根据官网文档的指引，在本地客户端的配置文件 (`cpolar.yml`) 中使用你保留的这个隧道信息，这样每次启动后，公网地址都是固定不变的。
    

这个免费功能对于需要长期进行 Webhook 测试、远程访问个人 NAS 或树莓派等场景非常实用。

#### 2. 付费方案：绑定自己的域名

如果你想使用自己的域名（例如 `dev.mydomain.com`），则需要升级到 cpolar 的付费套餐。

**操作步骤：**

1. 升级到基础版或更高级别的套餐。
    
2. 在 cpolar 后台绑定你自己的域名。
    
3. 根据指引，去你的域名提供商（如阿里云、腾讯云、Cloudflare）那里，**添加一条 CNAME 解析**，将你的域名指向 cpolar 提供的地址。
    
4. 配置本地客户端使用该域名启动隧道。

### 二、 ngrok：付费方案提供稳定域名

ngrok 的免费版域名是临时的、随机的。要获得固定域名，**必须升级到其付费计划**。

#### 1. 付费方案：预留子域名 (Reserved Subdomains)

升级到付费计划（如 Personal Plan）后，你可以在 ngrok 的仪表盘中预留一个或多个你喜欢的 `*.ngrok.app` 的子域名。

**操作步骤：**

1. **订阅付费计划：** 在 ngrok 官网选择并订阅一个付费套餐。
    
2. **登录后台创建域名：** 在仪表盘的 "Cloud Edge" -> "Domains" 中，点击 "New Domain" 或 "Create Domain"。
    
3. **预留子域名：** 你可以注册一个属于你的、独一无二的子域名，例如 `my-awesome-app.ngrok.app`。
    
4. **在本地使用该域名启动：**
    
    Bash
    
    ```
    # 以前免费版只能用 ngrok http 3000
    # 现在可以用 --subdomain 参数指定你预留的域名
    ngrok http --subdomain=my-awesome-app 3000
    ```
    
    这样，无论你重启多少次，访问 `https://my-awesome-app.ngrok.app` 都会指向你本地的 `3000` 端口。
    

#### 2. 付费方案：绑定自定义域名 (Custom Domains)

如果你想使用自己的域名，通常需要更高级别的付费计划。

**操作步骤：**

1. **订阅支持自定义域名的计划。**
    
2. **在 ngrok 后台添加你的域名：** 例如 `dev.yourdomain.com`。
    
3. **配置 DNS：** ngrok 会提供一个 CNAME 记录值（例如 `xxxxxxxx.cname.ngrok-custom.com`）。你需要去你的域名提供商那里，将 `dev.yourdomain.com` 的 CNAME 记录指向这个地址。
    
4. **在本地使用该域名启动：**
    
    Bash
    
    ```
    ngrok http --domain=dev.yourdomain.com 3000
    ```

### 三、 终极方案：使用 frp + 自有服务器和域名

如果你追求**完全的控制权**和**最低的长期成本**，并且不介意进行一次性的技术配置，那么自建 `frp` 服务是最佳选择。

**你需要：**

1. 一台拥有公网 IP 的云服务器（VPS），最低配置即可，成本可能比订阅 ngrok/cpolar 更低。
    
2. 一个属于你自己的域名。
    

**操作步骤：**

1. **域名解析：** 将你的域名（例如 `*.dev.yourdomain.com`）通过 A 记录解析到你的云服务器 IP。
    
2. **部署 frps：** 在云服务器上安装并运行 `frps`（服务端），并配置 `vhost_http_port` 和 `subdomain_host`。
    
3. **部署 frpc：** 在本地开发机上安装并运行 `frpc`（客户端），配置 `server_addr` 指向你的服务器 IP，并设置你想要的 `subdomain`，例如 "my-app"。
    

完成配置后，你就可以通过 `http://my-app.dev.yourdomain.com` 稳定地访问你本地的服务了。这个域名是永久有效的，只要你的服务器和域名不续费。

### 结论与建议

- **追求免费和简单：** 选择 **cpolar 免费版**，通过后台预留一个固定子域名，完全能满足个人长期的基本需求。
    
- **追求专业和品牌化：** 如果你需要使用自己的域名，并且看重 ngrok 强大的生态和稳定性，**升级到 ngrok 付费版** 是最专业的选择。
    
- **追求完全控制和性价比：** 如果你有一定的技术能力，**自建 frp 服务** 是最灵活、最具成本效益的终极解决方案。


#  Cloudflare Tunnel 隧穿
当然可以，而且这正是 Cloudflare Tunnel 最核心和最强大的功能之一。**Cloudflare Tunnel 不仅可以提供长久的域名，而且它必须与一个长久（即您自己拥有）的域名配合使用。**

简单来说，Cloudflare Tunnel 的工作模式就是将**您自己的域名**安全地连接到您本地运行的服务上，从而实现永久、稳定、安全的内网穿透。

这里为您详细解析它的两种“长久域名”模式：

### 1. 使用您自己的域名（主要且推荐的方式）

这是 Cloudflare Tunnel 的标准用法。您需要拥有一个自己的域名（例如 `mydomain.com`），然后将其添加到您的 Cloudflare 账户进行管理。

**工作流程：**

1. **拥有一个域名：** 您需要先从任何域名注册商（如 GoDaddy, Namecheap, 阿里云, 腾讯云等）购买一个域名。
    
2. **将域名添加到 Cloudflare：** 在 Cloudflare 官网注册一个免费账户，然后按照指引添加您的域名。这个过程需要您去域名注册商那里，将域名的 DNS nameservers（域名服务器）修改为 Cloudflare 提供的地址。
    
3. **创建 Tunnel：** 在 Cloudflare Zero Trust 仪表盘中创建一个 Tunnel。
    
4. **配置公共主机名 (Public Hostname)：** 这是关键一步。您可以为您的 Tunnel 配置一个或多个公共主机名，例如：
    
    - `nas.mydomain.com` -> 指向您本地的 NAS 服务 (`http://192.168.1.10:5000`)
        
    - `blog.mydomain.com` -> 指向您本地的博客 (`http://localhost:2368`)
        
    - `ssh.mydomain.com` -> 指向您本地的 SSH 服务 (`ssh://localhost:22`)
        

**这个域名是完全长久和固定的。** 只要您为您的域名续费，并且 Cloudflare Tunnel 客户端 (`cloudflared`) 在您的内网设备上持续运行，这些子域名就可以一直稳定地访问您本地的服务。

**优点：**

- **完全免费：** Cloudflare Tunnel 的核心功能对于个人用户是完全免费的。
    
- **品牌化和专业：** 使用您自己的域名，看起来非常专业。
    
- **极其安全：** 所有流量都通过 Cloudflare 的全球网络进行加密和保护，您的服务器真实 IP 地址完全不会暴露在公网上。
    
- **功能强大：** 可以免费获得 Cloudflare 提供的 CDN 加速、DDoS 防护、WAF（Web 应用防火墙）等强大功能。
    
- **集成 Zero Trust 访问控制：** 您可以轻松地为您的服务添加一层访问控制，例如要求通过邮箱 OTP、GitHub 账号、Microsoft 账号等方式登录后才能访问，极大地增强了安全性。
    

### 2. 使用 TryCloudflare 进行临时分享（非长久）

Cloudflare 也提供了一个类似 ngrok 免费版的功能，叫做 "Quick Tunnels" 或 "TryCloudflare"。它会生成一个临时的、随机的域名，用于快速测试和分享，**但这个域名不是长久的。**

使用方法：

您可以在本地直接运行一条命令来启动一个临时隧道：

Bash

```
cloudflared tunnel --url localhost:8080
```

这会生成一个类似 `https://random-words-and-numbers.trycloudflare.com` 的 URL。

**特点：**

- **临时性：** 这个 URL 是临时的，通常在隧道关闭 24 小时后就会失效。
    
- **无需域名：** 您不需要拥有自己的域名即可使用。
    
- **适用场景：** 非常适合临时向同事或朋友演示本地项目、调试 Webhook 等一次性任务。
    

### 结论与对比

|特性|**Cloudflare Tunnel (配合自有域名)**|**TryCloudflare (Quick Tunnels)**|
|---|---|---|
|**域名持久性**|**永久** (只要域名有效)|**临时** (会过期)|
|**域名类型**|**自定义域名** (`sub.yourdomain.com`)|随机生成的 `*.trycloudflare.com`|
|**前提条件**|**需要拥有一个自己的域名**|无需任何前提|
|**安全性**|**极高**，可集成 Zero Trust 访问策略|高，流量同样加密|
|**推荐场景**|**长期、稳定地发布服务** (如个人博客、NAS、远程桌面)|**临时、快速的开发与分享**|
|**成本**|**免费** (仅需支付域名本身的年费)|**完全免费**|

**总结：**

如果您需要一个**长久的、固定的公网域名**来访问您的内网服务，**Cloudflare Tunnel 是目前市面上最强大、最安全、且成本最低（近乎免费）的选择之一**。它的核心就是利用您自己的长久域名来实现永久的隧穿。临时分享的 TryCloudflare 功能只是一个补充，不能满足长久使用的需求。
