### 核心问题：为什么需要内网穿透？

要理解内网穿透，首先要明白“内网”和“NAT”这两个概念。

- **内网（私有网络）**：大多数家庭和公司的设备都位于一个路由器或防火墙后面，构成一个局域网（LAN）。这些设备被分配的是私有IP地址（如 `192.168.1.100`）。这些地址只能在局域网内部通信，无法被公共互联网直接访问。
    
- **NAT (Network Address Translation, 网络地址转换)**：你的路由器只有一个公网IP地址，这是它在互联网上的唯一标识。当你内网的设备访问互联网时，路由器会将你的私有IP地址“翻译”成它的公供IP地址。这个过程就是NAT。
    

**核心矛盾在于**：NAT机制是单向的。内网设备可以主动访问外网，但外网设备无法主动找到并访问你内网中的某一台具体设备，因为它不知道你的私有IP，只能看到路由器的公网IP。

**内网穿透（NAT Traversal）的目标就是解决这个矛盾，让外网设备能够安全、稳定地访问到位于内网特定设备上的服务（如Web服务器、远程桌面、SSH、游戏服务器等）。**

### 内网穿透的核心原理

无论哪种工具或方法，内网穿透的实现都离不开一个关键角色：**一台拥有公网IP的服务器（我们称之为“中转服务器”或“穿透服务器”）**。

其基本思路是：**既然内网设备可以主动连接外网，那么就让内-网设备主动与中转服务器建立一个持久的连接通道。外网的访问者实际上是访问中转服务器，然后中转服务器再通过之前建立好的通道，将请求转发给内网设备。**

下面是几种主流的实现原理：

#### 1. 反向隧道 / 端口转发 (Reverse Tunneling)

这是最常用、最稳定的原理，也是`frp`、`ngrok`这类工具的核心。

- **步骤1：建立隧道**
    
    - 内网的客户端程序（例如frp client）主动连接到公网的中转服务器（frp server），并告诉服务器：“你好，我想把我的 `192.168.1.100:80` 这个Web服务暴露出去，请给我开一个公网端口，比如 `6000`。”
        
    - 中转服务器收到请求后，会开启自己的 `6000` 端口，并与内网客户端建立一个长期保持的连接通道（隧道）。
        
- **步骤2：公网访问**
    
    - 一个外部用户想访问你的内网站点，他访问的是 `中转服务器的公网IP:6000`。
        
    - 中转服务器监听到 `6000` 端口有请求进来，它不做任何处理，直接通过之前建立好的隧道，将这个请求原封不动地“扔”给内网客户端。
        
- **步骤3：内网响应**
    
    - 内网客户端收到请求后，将其转发给本地的Web服务（`127.0.0.1:80`）。
        
    - Web服务处理完请求，将响应数据返回给内网客户端。
        
    - 内网客户端再通过隧道将响应数据传回给中转服务器。
        
    - 最后，中转服务器将响应数据返回给外部访问用户。
        
- **优点**：非常稳定、可靠，可以穿透几乎所有类型的NAT。
    
- **缺点**：所有流量都需要经过中转服务器，带宽和速度受限于服务器的性能和网络质量。
    

#### 2. UDP打洞 (UDP Hole Punching)

这种技术主要用于P2P（点对点）连接，例如语音/视频通话、联机游戏等，目标是让两个处于不同内网的设备直接通信，而不需要中转服务器来转发所有数据。

- **原理**：
    
    1. A和B都想直接通信，它们首先都连接到一个公网的协调服务器（Rendezvous Server）。
        
    2. 协调服务器记录下A和B的公网IP和端口号（由它们的路由器NAT分配的）。
        
    3. 服务器将B的公网地址信息告诉A，同时将A的信息告诉B。
        
    4. A和B拿到对方的公网地址后，**同时**向对方的地址发送UDP数据包。
        
    5. 当数据包发出时，双方的路由器都会在自己的NAT表中“凿开”一个洞，认为这个连接是合法的。由于双方同时操作，数据包就可能正好穿过这个“洞”到达对方，从而建立直接连接。
        
- **优点**：一旦连接建立，数据传输速度快，不消耗中转服务器的带宽。
    
- **缺点**：成功率不是100%，会受到路由器NAT类型的限制（特别是对称型NAT）。

### 如何进行内网穿透（常用方法）

#### 方法一：使用成熟的SaaS服务（简单、开箱即用）

这类服务提供商已经帮你搭建好了所有公网服务器，你只需要在内网设备上运行一个客户端软件即可。

- **代表工具**：
    
    - **Ngrok**: 国际上最知名的内网穿透服务，提供免费套餐（有随机域名、限速等限制）和付费套餐。使用非常简单，一条命令即可启动。
        
    - **花生壳 (PeanutHull)**：国内老牌服务商，提供动态域名解析（DDNS）和内网穿透服务。也有免费版本和不同等级的付费服务。
        
    - **cpolar**: 近年来在国内较为流行，提供稳定的免费和付费穿透服务，配置简单。
        
- **操作步骤 (以Ngrok为例)**：
    
    1. 去Ngrok官网注册账号，获取你的Authoken。
        
    2. 下载并解压Ngrok客户端。
        
    3. 在终端执行命令，配置token：`./ngrok authtoken YOUR_AUTHTOKEN`
        
    4. 启动穿透，比如将本地的8080端口穿透出去：`./ngrok http 8080`
        
    5. Ngrok会为你生成一个公网可访问的随机域名（如 `https://random-string.ngrok.io`），访问这个域名就等于访问你本地的 `localhost:8080`。
        

#### 方法二：自建穿透服务（灵活、高性价比）

如果你有一台云服务器（如阿里云、腾讯云等），你可以利用开源工具自己搭建中转服务，实现完全由自己掌控的内网穿透。

- **代表工具**：
    
    - **frp**: 一个功能强大、高性能、开源的反向代理工具。是目前自建穿透的首选，配置灵活，支持TCP, UDP, HTTP, HTTPS等多种协议。
        
    - **NPS**: 一款功能与frp类似，但提供了Web管理界面的工具，配置和管理更加直观。
        
- **操作步骤 (以frp为例)**：
    
    1. **准备**：一台有公网IP的云服务器。
        
    2. **服务器端配置 (frps)**：
        
        - 在云服务器上下载并解压frp。
            
        - 编辑配置文件 `frps.ini`，最简单的配置就是设置一个监听端口：
            
            Ini, TOML
            
            ```
            [common]
            bind_port = 7000 
            ```
            
        - 在服务器上启动frp服务端：`./frps -c ./frps.ini`
            
    3. **客户端配置 (frpc)**：
        
        - 在内网设备上下载并解压frp。
            
        - 编辑配置文件 `frpc.ini`，配置服务器地址和要穿透的服务：
            
            Ini, TOML
            
            ```
            [common]
            server_addr = 你的服务器公网IP
            server_port = 7000
            
            [web]
            type = tcp
            local_ip = 127.0.0.1
            local_port = 80
            remote_port = 6000 
            ```
            
            这个配置的意思是，将本地的80端口映射到服务器的6000端口。
            
        - 在内网设备上启动frp客户端：`./frpc -c ./frpc.ini`
            
    4. **访问**：现在访问 `你的服务器公网IP:6000` 就会被转发到你内网设备的80端口了。
        

#### 方法三：P2P组网工具（虚拟局域网）

这类工具不只是简单的端口转发，而是通过P2P技术（可能包含UDP打洞）在多个设备之间创建一个加密的虚拟局域网。一旦组网成功，你的所有设备（无论在不在同一个内网）都好像在同一个路由器下面一样，可以直接通过分配的虚拟IP地址互相访问。

- **代表工具**：
    
    - **ZeroTier**: 配置简单，免费套餐支持最多25个设备。它为每个设备分配一个固定的虚拟IP，你可以直接用这个IP访问设备上的任何端口，非常方便。
        
    - **Tailscale**: 基于WireGuard协议，同样非常易于使用和配置，安全性高。
        
- **操作步骤 (以ZeroTier为例)**：
    
    1. 在ZeroTier官网注册账号，创建一个虚拟网络（会得到一个Network ID）。
        
    2. 在你需要组网的所有设备上（你的电脑、家里的NAS、云服务器等）都安装ZeroTier客户端。
        
    3. 将所有客户端加入到你创建的那个网络ID中。
        
    4. 在官网的管理后台，授权这些设备加入网络。
        
    5. 之后，你就可以在任何一台设备上，通过另一台设备的虚拟IP地址直接访问它了。
        

### 总结

| 方法                    | 优点                        | 缺点                         | 适用场景                    |
| --------------------- | ------------------------- | -------------------------- | ----------------------- |
| **SaaS服务 (Ngrok等)**   | **极其简单**，无需公网服务器，快速验证     | 免费版限制多（速度、域名），数据经过第三方      | 临时开发调试、快速分享演示           |
| **自建服务 (frp等)**       | **完全可控**，性能好，成本低（已有服务器的话） | 需要一台公网服务器，有一定配置门槛          | 长期、稳定的个人服务（网站、NAS、远程桌面） |
| **P2P组网 (ZeroTier等)** | **安全方便**，像在一个局域网内，可访问任意端口 | 连接建立可能受网络环境影响，初始连接依赖其中央服务器 | 多设备安全组网，远程办公，管理多台服务器    |
# 花生壳怎么做，有硬件么
好的，关于花生壳（PeanutHull）如何使用以及是否有硬件，我们来详细说明一下。

花生壳是国内非常老牌和知名的内网穿透及动态域名解析（DDNS）服务商。它提供了纯软件和软硬件结合的多种解决方案，来满足不同用户的需求。

### 花生壳怎么做？（软件方式）

对于大多数普通用户和开发者来说，使用花生壳的软件客户端是最常见、最直接的方式。这种方式的原理就是我们在之前讨论过的反向隧道技术。

**核心步骤如下：**

1. **注册账号**：访问花生壳官网（oray.com），注册一个Oray账号。
    
2. **下载并安装客户端**：
    
    - 在需要被访问的内网设备上下载并安装花生壳客户端。
        
    - 花生壳支持多种操作系统，包括 Windows、macOS、Linux，甚至还有针对树莓派、NAS（如群晖、威联通）等设备的特定版本。
        
3. **登录客户端并添加映射**：
    
    - 打开并登录花生壳客户端。
        
    - 在客户端的管理界面中，找到“内网穿透”或类似的功能入口，点击“添加映射”。
        
4. **配置端口映射规则**：
    
    - **应用名称**：给你的服务起一个容易识别的名字，例如“我的网站”、“远程桌面”。
        
    - **映射类型**：选择你的服务类型。通常是 **HTTP/HTTPS**（用于网站）或 **TCP**（用于远程桌面、SSH、数据库、游戏服务器等）。
        
    - **外网域名/端口**：花生壳会免费赠送你一个二级域名（例如 `xxxxx.imwork.net`）。对于HTTP/HTTPS，外网端口通常是80/443。对于TCP，它会分配一个随机的外网端口号。付费服务可以自定义域名和选择固定端口。
        
    - **内网主机及端口**：填写你这台设备的内网IP地址（例如 `192.168.1.101`）以及你服务的端口号（例如网站是 `80`，Windows远程桌面是 `3389`）。
        
    - **带宽**：免费版通常有1GB/月的流量和1Mbps的带宽限制。如果需要更高的速度和更大的流量，需要付费升级。
        
    - 点击“确定”保存。
        
5. **访问**：
    
    - 映射添加成功后，花生壳客户端会显示一个“外网访问地址”。
        
    - 现在，你或任何在互联网上的人，都可以通过这个地址（例如 `http://xxxxx.imwork.net` 或 `xxxxx.imwork.net:12345`）来访问你部署在内网的设备和服务了。
        

**总结来说，软件方式就是：注册 -> 下载客户端 -> 登录 -> 添加映射 -> 获取外网地址 -> 访问。**

### 花生壳有硬件吗？答案是：有的

花生壳确实提供专门的硬件产品，通常被称为“花生壳盒子”或“花生壳智能硬件”。这些硬件本质上是一台预装并优化了花生壳内网穿透服务的迷你Linux电脑。

**为什么需要硬件盒子？**

使用纯软件客户端有一个前提：**你必须让运行客户端的那台电脑或设备一直开着机**。如果电脑关机、休眠或客户端程序关闭，内网穿透就会中断。

花生壳硬件盒子的出现就是为了解决这个问题，它带来了几个核心优势：

1. **7x24小时稳定运行**：硬件盒子功耗极低（通常只有几瓦），可以全年无休地插在路由器旁边稳定运行，确保你的内网穿透服务永远在线。
    
2. **解放电脑**：你不再需要在你的个人电脑或服务器上一直运行着客户端软件，避免了因电脑操作（如关机、重启）导致服务中断的麻烦。
    
3. **即插即用，管理方便**：硬件通常设计得非常简单，只需要接上电源和网线即可。所有的映射配置都可以通过网页端的管理后台或手机App来远程完成，无需接触设备本身。
    
4. **内嵌DDNS功能**：除了内网穿透，这些硬件也内嵌了动态域名解析功能。即使你的宽带是动态公网IP，它也能自动将你的域名解析到最新的IP地址上。
    

**花生壳硬件产品有哪些？**

花生壳推出过多款硬件，例如：

- **花生壳盒子**：比较经典的产品，专注于提供稳定的内网穿透服务。
    
- **蒲公英路由器**：这是Oray（花生壳母公司）推出的另一系列硬件，它本身是一个企业级路由器，但深度集成了“智能组网”（类似于ZeroTier的虚拟局域网）功能，比单纯的端口映射更强大，可以将多个不同地点的局域网虚拟成一个大局域网，实现设备之间的内网IP互访。
    

**如何使用花生壳硬件？**

1. **购买硬件**：根据需求选择合适型号的硬件盒子。
    
2. **连接设备**：将硬件盒子用网线连接到你的主路由器上，并接通电源。
    
3. **设备绑定**：通过手机App扫描硬件背面的二维码，或通过电脑访问指定地址，将硬件设备绑定到你的Oray账号下。
    
4. **远程配置**：登录花生壳的管理后台（https://www.google.com/search?q=b.oray.com），找到你的硬件设备，然后像使用软件客户端一样，在Web界面上添加和管理端口映射规则。之后的所有流量都会通过这个硬件盒子进行转发。

**结论：**

- 如果你需要**长期、可靠地**将内网服务（如网站、NAS、私有云盘、监控录像）暴露到公网，强烈建议购买一个**花生壳硬件盒子**，它能提供更好的稳定性和便利性。


# cloudflare内网穿透
好的，Cloudflare 确实提供了一个非常强大、安全且在很多场景下免费的内网穿透解决方案，它的正式名称叫做 **Cloudflare Tunnel**。

这个功能以前是其付费产品 Argo 的一部分（曾叫 Argo Tunnel），但现在 Cloudflare 已将其免费开放，并整合进了其 **Zero Trust** 安全框架中，使其不仅是一个穿透工具，更是一个安全接入内网服务的通道。

### Cloudflare Tunnel 的工作原理

与我们之前讨论的 frp、Ngrok 等工具的原理（客户端连接服务器，服务器开端口等待访问）略有不同，Cloudflare Tunnel 的方式更加巧妙和安全：

1. **建立出站连接 (Outbound Connection)**：
    
    - 你需要在你的内网服务器（你想暴露的设备，如 NAS、Web 服务器等）上安装一个名为 `cloudflared` 的轻量级守护进程（daemon）。
        
    - `cloudflared` 启动后，会主动向 Cloudflare 的全球边缘网络建立多个持久、加密的**出站连接**。它会连接到离你最近的两个 Cloudflare 数据中心，以实现高可用和负载均衡。
        
2. **流量路由**：
    
    - 你需要在 Cloudflare 的仪表板上配置一个域名（例如 `service.yourdomain.com`）指向这个建立好的 Tunnel。
        
    - 当有用户访问 `service.yourdomain.com` 时，这个请求会首先到达 Cloudflare 的边缘网络。
        
    - Cloudflare 的边缘节点收到请求后，**不会将流量转发给你路由器的公网IP**（这是关键区别），而是通过之前 `cloudflared` 建立好的那个加密隧道，将请求直接推送给你内网的 `cloudflared` 进程。
        
3. **内网转发**：
    
    - `cloudflared` 收到请求后，再根据你的配置，将流量转发给你内网的真实服务（例如 `localhost:8080` 或 `192.168.1.10:80`）。
        
    - 内网服务的响应也沿着这条加密隧道原路返回给 Cloudflare，最终送达访问用户。
        

### Cloudflare Tunnel 的核心优势

1. **极致的安全性**：
    
    - **隐藏源站IP**：你的服务器不需要暴露任何公网IP地址，甚至可以关闭路由器上的所有入站端口。因为连接是由内网主动发起的，攻击者无法扫描到你的服务器，从根本上杜绝了针对服务器IP的直接攻击（如DDoS）。
        
    - **与 Zero Trust 集成**：你可以非常轻松地在 Tunnel 前面加上一层身份验证。例如，要求访问者必须通过邮箱一次性密码、GitHub/Google账号登录，甚至更复杂的设备状态检查后才能访问你的内网服务。这意味着，即使域名泄露，没有权限的人也根本无法看到你的登录页面。
        
    - **全程加密**：流量从用户到Cloudflare边缘节点，再从边缘节点到你的内网服务器，全程都是加密的。
        
2. **高性能和高可靠性**：
    
    - **利用全球网络**：你的服务将受益于 Cloudflare 庞大的全球Anycast网络，用户会被路由到离他们最近的数据中心，加快了访问速度。
        
    - **内置负载均衡和冗余**：`cloudflared` 会同时连接到多个Cloudflare数据中心，如果一个出现问题，流量会自动切换，保证了服务的稳定性。
        
3. **完全免费**：
    
    - 对于绝大多数个人和小型团队来说，Cloudflare Tunnel 的核心功能是完全免费的。你只需要拥有一个自己的域名，并将其NS服务器托管在Cloudflare即可（这也是免费的）。
        
4. **功能强大**：
    
    - 不仅支持 HTTP/HTTPS，还支持 TCP、UDP、SSH、RDP 等几乎所有协议的转发。你可以用它来远程桌面、SSH连接服务器、玩游戏等。
        

### 如何设置 Cloudflare Tunnel？

设置过程主要在 Cloudflare 的 Zero Trust 仪表板中完成，非常直观。

**前提：** 你需要拥有一个自己的域名，并已将其添加到 Cloudflare 账户中。

**步骤概览：**

1. **进入 Zero Trust 仪表板**：
    
    - 登录你的 Cloudflare 账户。
        
    - 在左侧菜单中，找到并点击 **“Zero Trust”**。如果是首次使用，需要走一个简单的引导设置流程（选择免费计划即可）。
        
2. **创建 Tunnel**：
    
    - 在 Zero Trust 仪表板的左侧菜单，选择 **Access -> Tunnels**。
        
    - 点击 **“Create a tunnel”**。
        
    - 选择 **“Cloudflared”**作为连接器类型，然后给你的 Tunnel 起一个名字（例如 `my-home-server`），点击保存。
        
3. **安装并运行 Connector (`cloudflared`)**：
    
    - 接下来，Cloudflare 会为你生成一条安装命令。你需要根据你内网服务器的操作系统（Windows, macOS, Linux Docker等）选择对应的命令。
        
    - 这条命令通常是一行完整的指令，包含了你的账户授权 token。你只需在你的内网服务器的终端中复制并运行它。
        
    - **例如，在Linux上，命令通常是这样：**
        
        Bash
        
        ```
        curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb &&
        sudo dpkg -i cloudflared.deb &&
        sudo cloudflared service install YOUR_TOKEN_HERE
        ```
        
    - 运行成功后，`cloudflared` 就会作为系统服务在后台自动运行。回到Cloudflare仪表板，你应该能看到你的 Tunnel Connector 显示为“Healthy”状态。
        
4. **配置 Public Hostname (路由流量)**：
    
    - 点击你的 Tunnel，进入配置页面，选择 **“Public Hostname”** 标签页。
        
    - 点击 **“Add a public hostname”**。
        
    - **Subdomain/Domain**: 填写你想用来访问的域名，例如子域名 `nas`，域名选择 `yourdomain.com`。
        
    - **Service Type**: 选择协议，例如 `HTTP`。
        
    - **URL**: 填写内网服务的地址和端口，例如 `localhost:5000` 或 `192.168.1.10:8080`。
        
    - 你还可以在 **Additional settings** 中配置更高级的选项。
        
    - 点击 **“Save hostname”**。
        
5. **访问和测试**：
    
    - 等待DNS记录生效（通常很快）。
        
    - 现在，打开浏览器，访问你刚刚设置的域名 `nas.yourdomain.com`，你就应该能看到你内网的服务界面了。整个过程流量都通过了Cloudflare的安全隧道。
        

**可选：增加 Zero Trust 访问策略**

为了让你的服务更安全，你可以创建一个 **Application** 并为其配置策略：

- 在 **Access -> Applications** 中，添加一个“Self-hosted”应用。
    
- 配置应用的子域名为你 Tunnel 使用的域名。
    
- 在下一步中，为应用设置策略，例如“只允许我的Google邮箱账号（`myemail@gmail.com`）访问”。
    
- 保存后，当任何人访问 `nas.yourdomain.com` 时，都必须先通过 Cloudflare Access 的登录页面进行身份验证，通过后才能看到你的内网服务。
    

总之，Cloudflare Tunnel 是目前功能最强大、最安全、性价比最高的内网穿透方案之一，特别适合有自己域名的用户长期、稳定地暴露内网服务。
