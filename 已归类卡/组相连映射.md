Cache 分成了 4 组，并且是 2 路组相连


- **Cache 结构:** 分成 8 个 Block, **分成 4 组**, 2 路组相连 (每组 2 个 Block)
- **主存结构:** 分成 32 个 Block
- **Block 大小:** 4 字节
- **映射方式:** 2 路组相连映射， 4 组

**计算步骤：**

1. **计算 Cache 的组数 (Number of Sets):**
    
    - 题目已经明确说明 Cache 分成 **4 组 (Sets)**。
    - 组数 = **4 组**。
2. **确定 Offset 位数 (Offset Field Size):**
    
    - Block 大小为 4 字节，需要 2 位来表示块内偏移 (22 = 4)。
    - Offset 字段 = **2 位**。
3. **确定 Index 位数 (Index Field Size):**
    
    - Cache 分成了 4 组， 需要用 Index 来选择这 4 个组。
    - 索引 4 组需要 **2 位** (22 = 4)。
    - Index 字段 = **2 位**。
4. **确定 Tag 位数 (Tag Field Size):**
    
    - 主存被分成 32 个 Block，每个 Block 4 字节，总共 128 字节。
    - 寻址 128 字节的主存空间需要 7 位地址 (27 = 128)。
    - Tag 位数 = 总地址位数 - Index 位数 - Offset 位数 = 7 位 - 2 位 - 2 位 = **3 位**。
5. **将主存地址 15H 转换为二进制 (7 位):**
    
    - 15H 是十六进制，等于十进制的 21。
    - 21 转换为 7 位二进制： **0010101B**
6. **提取 Tag, Index, Offset：**
    
    - 根据计算的位数分配，从 7 位二进制地址 `0010101B` 中提取：
        - **Tag (最高 3 位):** `001B`
        - **Index (中间 2 位):** `01B`
        - **Offset (最低 2 位):** `01B`
7. **将二进制的 Tag, Index, Offset 转换为十六进制：**
    
    - **Tag:** `001B` = 1 (十进制) = **1H**
    - **Index:** `01B` = 1 (十进制) = **1H**
    - **Offset:** `01B` = 1 (十进制) = **1H**

**验证 Index 和组号的计算逻辑:**

- 主存 Block 号 = 字节地址 / Block 大小 = 21 / 4 = 5 (向下取整，Block 编号从 0 开始)
- 组号 (Set Index) = 主存 Block 号 mod 组数 = 5 mod 4 = 1
- 组号 1 对应的 Index 值通常用二进制 `01` 或十六进制 `1H` 表示，与我们上面分析的 Index 结果一致。

**最终答案：**

对于访问主存地址 15H，在 2 路组相连， 4 组的 Cache 中，tag、index 和 offset 分别是：

- **Tag:** **1H**
- **Index:** **1H**
- **Offset:** **1H**

**总结关键步骤：**

- **理解题意，明确组数和路数:** 题目描述可能有多重理解，需要仔细分析，并根据 Cache Block 总数来判断是 "X 路组相连， Y 组" 还是 "X 组， Y 路组相连"， 确保组数 * 路数 = Cache Block 总数。
- **正确计算 Index 位数:** Index 位数由 **组数** 决定，不是路数。 Index 用于选择访问哪个组。
- **灵活应用模运算验证 Index:** 使用 `主存 Block 号 mod 组数` 来验证 Index 值的正确性。
