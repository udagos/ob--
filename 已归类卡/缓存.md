# Cache原理
## catch结构
Cache Line

CacheLine是Cache中的最小缓存单位。例如221芯片的CacheLine容量大小是16字节, 地址位宽是32位,
## Cache的访问
在CPU执行程序过程中, 需要从主存读取指令或数据时, 先检查Cache中有没有要访问的信息
**若CPU访问单元的主存块在Cache中,则称Cache命中** (CacheHit)
## cache映射模式
为了把数据从主存读取到Cache, 必须把主存块地址映射到CacheLine, 这称作**地址映射**

由于Cache的存储空间较小, 因此Cache中的一个存储块要与主存中的若干个存储块相对应, 即若干个主存块将映象到同一个CacheLine
根据不同的地址对应方法, **地址映射的模式分为**直接映射、全相联映射和组相联映射三种。
### 直接映射 
直接映射的意思是, 每个**主存块只与一个缓存块相对应**
![](../fujian/Pasted%20image%2020250301185030.png)

i = j m o d C (i: 缓存的块号; j: 主存的块号, C: 缓存块数)

如图3.4所示, Cache分成4个Block, 主存分成32个Block, 每个Block的大小为4字节。本例中缓存块数为4, **因此MainMemory中每4个Block为一组,** 每组的第1块映射到Cache中的CacheBlock[0], 第2块映射到CacheBlock[1], 以此类推。

假设现在要访问主存中的地址15H, CPU首先会在Cache中查找, 这就需要将主存中15H地址映射到Cache中,  
**主存的地址被分成了三部分: tag、index、offset。**
15 H = 0001 01 01
其中offset (01) 表示在块内的偏移量,index (01) 表示在Cache的块号。主存每一组相同index的内存块将映射到Cache中的同一块位置,因此需要tag (0001) 来区分不同的组。
[[../note/解释25.3.1-19.49]]

valid bit (有效位) 是用来标记Cache Block是否有效的, 当根据Main Memory地址映射到Cache所在块之后会先检查valid bit是否有效, 只有在有效的情况下, 比较tag才有意义。如果无效, 直接判定cache缺失
### [[../已归类卡/全相联映射]]

全相联映射允许MainMemory中的每一个内存块映射到Cache中的任何一个位置上面, 只有当Cache中的Block全部被占用时, 才考虑替换
由于采用全相联映射, 主存的地址被分成了两部分: tag、offset。
![](../fujian/Pasted%20image%2020250301195716.png)
**需要逐一检验tag标签来判断数据是否在  Cache中, 通过offset来确定在Cache Block中的偏移量。**

优点: 全相联方法块冲突的概率低
缺点: 全相联 Cache 中块表查找的速度慢

### [[../已归类卡/组相连映射]]
“**折中方法**”

直接相连映射是MainMemory中的任一Block只能映射到Cache中唯一的Block,而组相联映射则是映射到Cache中唯一的组 (Group)(一组包含若干Block)
在同一Group中, 采用全相联映射, 在组外使用直接相连映射
![](../fujian/Pasted%20image%2020250301195907.png)
映射规则为:i=jmodC (i:Cache的组号, j: 主存的块号, C:Cache的组数)。

假设现在要访问主存中的地址15H, CPU首先会在Cache中查找, 
**主存的地址被分成了三部分: tag、index、offset。**

其中offset (01) 表示在块内的偏移量,index (01) 表示在Cache中的组号, 确定组号为Group[1]后, 再逐一匹配Group[1]中所有Block对应的tag, 最后定位15H在Cache中映射的位置。

**常见的Cache一般都采用的组相连的映射方式**

## catch的替换策略

当Cache使用容量接近上限时, 每存储一个新增的Cache元素都要淘汰一个或多个已存储的Cache元素。Cache替换算法是用于决策淘汰哪个缓存元素的一类算法
挖掘程序访存行为的时间局部性, 尽可能将未来最有可能被频繁访问到的数据保留在缓存中, 以提高缓存命中率

4种Cache的替换算法
### RAND (随机算法)
若Cache已满, 则随机选择一块替换
### FIFO (先进先出算法)
若Cache已满, 最先进入缓存中的数据, 则应该最早被替换掉。
### LFU (最不经常使用算法)
为每一个Cache块设置一个“计数器”, 用于记录每个Cache  块被**访问过几次**。当Cache满后替换“计数器”最小的。

曾经被经常访问的主存块在未来不一定会用到
### LRU (近期最少使用算法)
为每一个Cache块设置一个计数器, 用于记录每个Cache块已经**多久没被访问了**。当Cache满后替换计数器最大的

**基于时间局部性原理, 近期被访问过的主存块, 在不久的将来也很有可能被再次访问**
## cache的缓存策略

###   读
缓存命中时 , 直接从Cache中获取数据。

未命中时
#### Read Through
直接从内存中读取数据
#### Read Allocation
先把数据读取到Cache中, 并将相应Cache Line标记为有效, 再从Cache中读数据。

### 写
#### ==缓存命中时== ^65wgzj8o2
##### Write Through
数据**同时更新到缓存和内存。**
![](../fujian/Pasted%20image%2020250301202256.png)
##### Write Back
数据**只更新到缓存, 当需要替换缓存行时**, 才会更新内存中的数据, 
因此回写也称为延迟写入。

![](../fujian/Pasted%20image%2020250301202220.png)
缓存中的每个块都有一个标志位,用来指示缓存中存在的数据是被修改 (Dirty) 还是未修改 (Clean),  这就是 Dirty Bit (修改位)


#### 缓存不命中时
##### Write Allocation

缓存未命中时, 在 Write Allocation 中, 先从主存中读取数据, 将其写入到Cache中, 并将相应Cache Line  标记为有效, 然后将新的数据写入Cache Line中

**Write Allocation 通常与回写一起使用。因为一般在直写模式下, 会同时写缓存和内存。**
![](../fujian/Pasted%20image%2020250301204531.png)
##### Write Around

Write Around 也被称为 No Write Allocation, 在 Write Around 中, 数据直接写入/更新到主内存, 而不会影响缓存。

## cache一致性问题
**以下两种情况会导致缓存和内存数据不一致**
1) Cache中的数据发生了改变而没有更新到内存中, 当直接访问内存时, 读取的是内存中的旧数据。
2) 内存中的数据发生了改变而没有无效Cache, 当通过总线地址访问主存时, 读取的是Cache中的旧数据。

**以下是Cache一致性的常见应用问题**
通常我们会将片外SPI Flash配置为XIP模式。**XIP模式下, 读取Flash的时候通过内存地址访问, 数据可以被缓存; 写入Flash的时候通过发送命令的方式访问, 数据不可以被缓存**。
如果之前读取过SPI Flash, Cache中有缓存的数据, 此时Cache和内存中的数据是一致的。当擦除/写入之后,  由于是**通过命令的方式访问, 直接跳过了Cach**e, 导致内存数据是新的, Cache数据是旧的。当再次读取Flash时,  **由于Cache Hit, 会从Cache中读取到旧数据。**
因此在**==擦除/写入==SPIFlash之后需要CacheInvalidate, 将Cache置为无效**，**当再次读取Flash时会Cache Miss,  这时会从内存中读取新的数据。**

**DMA访问内存时无法被缓存。**
**Cache的存储硬件是SRAM, 所以单片机的内部SRAM一般不支持缓存功能, 而外部外挂的SDRAM通常支持缓存。**
如果之前读取过SDRAM, Cache中有缓存的数据, 此时Cache和内存中的数据是一致的。当使用DMA从内部  SRAM搬运数据到SDRAM以后, 由于DMA无法使用缓存功能, 导致SDRAM存放的是新数据, Cache中缓存的是旧数据。当再次读取SDRAM时, 由于Cache Hit, 会从Cache中读取到旧数据。
因此在使用DMA**从内部SRAM搬运数据到SDRAM**之后需要CacheInvalidate, 将Cache置为无效

Write Back模式下, 如果之前写入过SDRAM, 此时Cache中还有未写回到内存的新数据。当使用DMA从内部  SDRAM搬运数据到SRAM时, 由于DMA无法使用缓存功能, 导致这次搬运的是旧数据。
因此在使用DMA**从SDRAM搬运数据到内部SRAM**之前需要CacheClean, 将Cache中的新数据写回SDRAM
