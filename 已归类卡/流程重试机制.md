### 流程重试机制

- **设计要求**：
    - 针对与外部硬件交互、易受物理环境干扰的关键执行流程（如电机驱动、切刀控制、传感器读取），必须建立重试机制。
    - 重试机制必须包含明确的 **重试次数上限** 和 **重试间隔时间**。
    - 硬件设计应尽可能提供 **闭环检测条件**（如电机堵转检测、传感器到位信号、编码器位置反馈），软件必须利用这些条件来判断操作是否真正成功。
    - 多次重试后依旧失败，系统应能进入一个明确的、安全可控的失败状态（如：记录错误日志、上报故障状态、亮起故障指示灯），并停止当前任务，防止故障扩大。

- **防御分析**：
    - 嵌入式系统的执行环境复杂，机械部件的瞬时卡顿、电源的瞬时波动或环境干扰都可能导致单次操作失败。重试机制能极大提高系统在面对这些瞬时、偶发性问题时的鲁棒性和成功率。
    - 增加硬件闭环检测，将“开环”的指令执行（“我认为它完成了”）升级为“闭环”的状态确认（“我确认它完成了”），是保证执行结果确定性的最可靠方法。
    - 若没有重试次数上限，当发生持续性故障（如电机完全卡死）时，程序会陷入死循环，不断重试，可能导致CPU资源耗尽、电机过热烧毁等更严重的问题。
    - 定义最终的失败状态，可以为后续的调试和维修提供明确的线索，也便于系统进行更高级别的故障处理（如：APP提示用户“打印机卡纸”)。

- **实例1：**

      **`项目`**：热敏票据打印机
      **`开发代表级别`**：中级
      **`问题描述`**：切刀机构因纸屑阻力或机械疲劳导致偶发性卡死，单次执行失败导致整个打印任务中断。

  1.  早期的切纸功能是一个简单的“开环”指令：
      ```C
      void Cutter_Cut(void)
      {
          // 仅执行电机驱动，不关心结果
          Motor_Start(MOTOR_CUTTER);
          Delay_ms(200); // 假定200ms内能完成
          Motor_Stop(MOTOR_CUTTER);
      }
      ```

  2.  这种设计在切刀受阻时，电机虽然执行了，但纸并未被切断。程序却认为任务已完成，继续后续流程（如吐出小票），导致用户拿到一张未切断的、混乱的票据。

  3.  **防御性设计**：硬件上增加切刀原位/终点传感器，或电机堵转检测功能。软件流程相应改造为具备重试能力的闭环控制。

      ```C
      #define CUTTER_EXEC_RETRY_MAX 3           // 最多重试3次
      #define CUTTER_EXEC_RETRY_INTERVAL_MS 50  // 每次重试间隔50ms
    
      BOOL Cutter_Cut_WithRetry(void)
      {
          U8 retry_count = 0;
    
          for (retry_count = 0; retry_count < CUTTER_EXEC_RETRY_MAX; retry_count++)
          {
              Motor_Start(MOTOR_CUTTER);
    
              // 等待硬件闭环信号（例如：终点传感器信号或堵转信号）
              if (Wait_Cutter_Finish_Status(200) == CUTTER_SUCCESS)
              {
                  Motor_Reset(MOTOR_CUTTER); //电机复位
                  return TRUE; // 执行成功
              }
    
              // 若失败，则进行复位和延时，准备重试
              Motor_Reset(MOTOR_CUTTER);
              Delay_ms(CUTTER_EXEC_RETRY_INTERVAL_MS);
          }
    
          // 多次重试后仍失败
          Log_Upload(LOG_LEVEL_ERROR, "Cutter cut failed after %d retries.", retry_count);
          System_SetStatus(SYS_STATUS_CUTTER_ERROR); // 设置系统为切刀错误状态
          return FALSE;
      }
      ```
  4.  改造后，即使发生单次卡纸，系统也会尝试自动恢复，只有在连续多次失败后才会上报确切的硬件故障，极大地提升了产品的稳定性和用户体验。

- **实例2：**

      **`项目`**：自动文档扫描仪
      **`开发代表级别`**：中级
      **`问题描述`**：进纸电机在输送纸张时发生卡纸，导致电机堵转，但系统未检测到，持续对电机供电，有烧毁风险。

  1.  设备通过驱动滚筒电机来送入纸张。初期的设计是启动电机后，延时一段固定的时间，并假定纸张已经走到位。
      ```C
      #define EXPECTED_FEED_TIME_MS 1000
    
      BOOL FeedPaper_Simple(void)
      {
           Motor_Start(MOTOR_FEED);
           Delay_ms(EXPECTED_FEED_TIME_MS);
           Motor_Stop(MOTOR_FEED);
         
           // 无任何检查，总是认为成功
           return TRUE;
      }
      ```

  2.  这种“开环”设计无法应对异常。如果纸张褶皱或多张纸吸附在一起导致卡纸，电机将堵转。此时程序依然会等待 `EXPECTED_FEED_TIME_MS`，在这期间电机持续过载，可能因过热而损坏。同时，软件认为进纸成功，会启动扫描头，最终扫描出一片空白或混乱的图像。

  3.  **防御性设计**：硬件上选用带有 **堵转检测（Stall Detection）** 功能的电机驱动芯片（如TMC系列驱动芯片），该芯片能在检测到电机堵转时通过一个引脚向MCU报告故障。软件必须利用此硬件闭环信号。

      ```C
      #define FEED_RETRY_MAX 3                // 最多重试3次
      #define FEED_RETRY_INTERVAL_MS 200      // 重试前等待200毫秒
      #define FEED_MOVE_TIMEOUT_MS 1500       // 单次进纸操作的最大允许时间
    
      BOOL FeedPaper_WithStallRetry(void)
      {
          U8 retry_count = 0;
    
          for (retry_count = 0; retry_count < FEED_RETRY_MAX; retry_count++)
          {
              U32 start_time = GetSystemTick();
              BOOL is_stalled = FALSE;
              BOOL is_success = FALSE;
    
              Motor_Start(MOTOR_FEED);
    
              // 等待进纸完成 或 堵转发生 或 超时
              while (GetSystemTick() - start_time < FEED_MOVE_TIMEOUT_MS)
              {
                  // 硬件闭环条件1: 检测到堵转信号
                  if (HW_GetMotorStallFlag() == TRUE) {
                      is_stalled = TRUE;
                      break; 
                  }
                  // 硬件闭环条件2: 纸张到位传感器被触发
                  if (HW_GetPaperPositionSensor() == PAPER_IN_PLACE) {
                      is_success = TRUE;
                      break;
                  }
              }
              Motor_Stop(MOTOR_FEED);
    
              // 检查退出循环的原因
              if (is_success) {
                  return TRUE; // 任务成功
              }
    
              // 如果因为堵转或超时而失败，则准备重试
              if (is_stalled) {
                  Log_Upload(LOG_LEVEL_WARN, "Paper jam detected! Retrying...");
                  // 尝试反转一小段以排除卡纸
                  Motor_Reverse(MOTOR_FEED, 50); // 假设反转50ms
              } else {
                   Log_Upload(LOG_LEVEL_WARN, "Paper feed timeout! Retrying...");
              }
    
              Delay_ms(FEED_RETRY_INTERVAL_MS);
          }
    
          // 所有重试均失败
          Log_Upload(LOG_LEVEL_ERROR, "FATAL: Paper feed failed after %d retries.", FEED_RETRY_MAX);
          System_SetStatus(SYS_STATUS_PAPER_JAM); // 设定系统为卡纸状态，并通知用户
          return FALSE;
      }
      ```
  4.  通过整合堵转检测和纸张位置传感器两个硬件闭环条件，系统能精确地得知电机执行的真实结果。在发生堵转时，它能立即停止电机以保护硬件，并尝试通过反转等策略自动修复。只有在反复尝试无效后，才将问题报告为严重的、需要用户干预的“卡纸”故障，大大提升了产品的可靠性和安全性。
