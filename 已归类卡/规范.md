# 固件编程规范
尽可能少的使用全局变量和静态变量
	在 C 语言中, 函数的 **static 局部变量是函数的记忆存储器, 会影响到函数的可重入性**。建议尽量少用 static 局部变量, 除非必需。
	不提倡使用全局变量, 尽量不要在头文件中出现象 extern int value 这类声明
	
用/#include <filename.h>格式来引用标准库的头文件 (编译器将从标准库目录开始搜索)
用 # includefilename . h 格式来引用非标准库的头文件 (编译器将从用户的工作目录开始搜索)

**尽可能在定义变量的同时初始化该变量 (就近原则), 指针必须初始化**
	如果引用了未被初始化的变量, 可能会导致程序错误
	**标识符前应加上前缀说明标识符的作用域** 
	g: 全局变量前缀, 表示 global
	s: 静态变量前缀, 表示 static
	m: 数据结构成员变量前缀, 表示 member

	**结构体定义时字段应从大到小进行定义**

当变量要求字节对齐时, 应使用 ALIGN 宏显性声明。ALIGN 宏可以作用于变量,  也可以作用于构造类型。

不可将浮点变量用\==或!=与任何数字比较千万要留意, 无论是 float 还是 double 类型的变量, 都有精度限制

**C 语言用 \# define 来定义常量 (称为宏常量)。C++语言除了 # define 外还可以用 const 来定义常量**


**函数尽量避免函数带有记忆功能**。相同的输入应当产生相同的输出
	在 C 语言中, 全局变量和 static 局部变量是函数的记忆存储器。**建议尽量少用全局变量和 static 局部变量**, 除非必需

**非调度函数应减少或避免使用控制参数, 尽量只是用数据参数**
![[Pasted image 20240910081832.png]]

参数的书写要完整
![[Pasted image 20240910081924.png]]
参数顺序要合理, 应按照源参数、目标参数、配置参数、返回参数的顺序排列

当**结构变量作为参数时, 应传送结构的指针**而不传送整个结构体

如果参数是指针, 且仅作输入用, 则应在类型前加 const

在函数体的入口处, 对参数的有效性进行检查
在函数体的出口处, 对 return 语句的正确性和效率进行检查。**return 语句不可返回指向栈内存的指针或者引用, 因为该内存在函数体结束时被自动销毁**
![[Pasted image 20240910082111.png]]

关键字 inline 必须与函数定义体放在一起才能使函数成为内联
关键字 inline 应体现在函数声明中

**编写可重入函数时,** 尽量避免使用全局变量。若**使用全局变量, 应通过关中断加以保护**
编写 C 语言的可重入函数时, 不应使用 static 局部变量, 否则必须经过特殊处理才能使函数具有可重入性
**使用互斥锁/信号量进行临界资源保护时, 需要避免在关闭调度的情况下获取临界资源, 以防止产生死锁。**
	**可重入该函数同时多个调用**


在中断服务程序中尽量避免使用延时操作
如果需要长延时, 可以使用定时器功能实现
若电机正转停止后需要延时启动反转, 可按下述方法处理: 在中断服务程序中停止电机, 设置延时定时周期, 重新启动定时器实现延时功能, 延时完成后, 再重新启动电机, 实现电机反转。
# 代码框架设计规范
![[Pasted image 20240910083231.png]]

## Applications

Application. c: 应用初始化, 主要用于固件设计的操作系统任务定义及初始化, 任务优先级定义、任务栈定义, 以及多模块应用的信号量、邮箱、消息等的初始化; Application. h: 应用初始化头文件, 主要用于头文件包含, 包含各个模块的头文件; MemoryConfig. h: 内存配置头文件, 主要用于系统使用的 DDR 以及 FLASH 内存的分配及配置; 
FunctionApp: 该文件夹存放功能模块相关的文件夹及文件, 例如 EEPROM 的配置、历史记录的记录项定义、日志的记录等级定义、通用算法等; 
其它: 其它文件夹放置与应用相关的模块, 在创建文件夹时
## Middlewares  
该文件夹存放中间层相关文件及文件夹, 中间层连接底层驱动层与应用层;
![[Pasted image 20240910083305.png]]
## Drivers
该文件夹存放驱动层相关文件及文件夹, 例如各器件的硬件驱动和单片机外设驱动, 单片机外设驱动都放入 PeripheralDriver 文件夹下, 与器件驱动同级目录。  
Drivers 文件夹下的文件夹 , 建议命名为 xxxDriver, 里面包含 xxxDriver. c 和  xxxDriver. h 文件。
![[Pasted image 20240910083401.png]]



固件在进行代码设计时, 整个工程中不允许出现大量的单个全局变量, 可以通过结构体将相关的变量放置在结构体中。

模块与中间层设计
	模块功能、逻辑控制与模块硬件驱动分离, 分别位于中间层和驱动层, 例: BldcOnBoard. c 和 BldcOnBoardDriver.c
	模块驱动接口固定, 模块驱动内部根据不同硬件平台自行实现, 模块直接调用模块驱动的接口。
	通过 ID 调用模块接口,
		![[Pasted image 20240910083525.png]]
	模块内结构体尽量不对外暴露

**同类器件不同类控制方式的处理**
	例: 一个 MCU 控制多个 BLDC, 一些 BLDC 由该 MCU 直接控制, 一些 BLDC 由该 MCU 发送命令通过另一个 MCU 控制。
	**这两种控制应在中间层封装成两个互相独立的模块**, 例: BldcOnBoard. c 和 BldcComm. c, 各自 ID 独立编号, 中间层不对这两个模块统一接口,**由应用层统一接口**。

各层函数接口名需要增加前缀, 驱动层->Drv, 中间层->Mid, 应用层->App (App: 只有当该文件作为基本模块需要被应用层其他文件调用时增加前缀)


在进行代码设计时, 应用层不直接调用底层的函数, 更不对处理器的寄存器进行直接操作

对于模块内部使用的宏定义, 建议在 C 源文件中实现定义, 而不体现在头文件中。
# 可移植
适当增加适配层, 以隐藏某一层的特定细节, 提供统一接口
	为了隐藏特定硬件平台的硬件特性, 增加硬件适配层 (比如, Android 中 HAL); 为在不同 Flash (比如, Nor、Nand 等)上支持各种嵌入式文件系统 (比如, UBIFS、JFFS 2 等), 增加 MTD 层, MTD 层对下隐藏不同类型 Flash 操作细节, 向上对不同文件系统提供统一操作接口。
编写代码要考虑数据对齐问题
编码中涉及到常量的, 必须使用宏定义, 禁止在代码中直接使用常量

在. c 和. h 文件包含头文件时, 禁止使用绝对路径

对常用的外设功能进行抽象封装, 提供统一的对外接口。比如: 各个平台的 GPIO 外设, 可以统一封装成 GPIO_Init ()、GPIO_Read ()、GPIO_Write (,), GPIO_SetDir ()等接口函数对外提供

**模块之间交互尽可能使用接口函数、信号量、邮箱、消息队列、事件等方式, 不用或者少用全局变量作为交互方式**

使用操作系统时要对线程、信号量、消息队列等基本应用进行封装, 以适应操作系统的切换

CPU 中断处理函数尽可能在最短的时间内处理完必须在中断中完成的任务, 其他**耗时多的任务进行线程化**, 在**中断处理函数中通过信号、消息队列、邮箱等方式通知任务处理线程**。对于不采用操作系统的编码设计, 要充分评估中断关闭对打印头选通、电机控制等时间敏感任务的影响。

编码中延时操作尽量使用定时器或者操作系统提供的延时函数
# 中断
进入中断服务程序后第一时间清除中断

**中断服务程序使用临界资源时, 需要增加互斥操作**。临界资源包括全局变量、共享内存、硬件接口 SPI、AD、串口等。临界资源的互斥操作包括在应用程序中增加 DI、EI, 中断嵌套时增加 DI、EI。

原则上硬件控制中断优先级最高, 例如功率器件控制、扫描行同步控制等; 其次为 UART、SPI、USB 等外设中断, 其中通讯中断以不丢失数据为前提尽可能降低优先级; 最后为定时中断及系统 TICK 中断; 对于中断嵌套, 需要考虑嵌套对整个系统的影响, 中断嵌套原则上不超过三级嵌套。

在中断设计时, 必须在初始化中断向量表后再使能中断。

在使用实时操作系统的设计中, 中断及其调用函数禁止出现死等信号量、消息队列、邮件等操作。

ARM 异常中断中, 增加功率器件的保护措施, 例如关闭打印头、电机。

**对于 DMA 数据发送及接收中断, 当 DMA 中断发生时, 数据不一定传输完毕, 可能有部分数据在硬件 FIFO 中, 例如 USB、SPI、UART 的 DMA 发送接收中断, 因此在中断设计时需要进行考虑并规避。**

在部分物理不可打断且处理时间较长的中断中, 必须考虑其执行时间对更高优先级中断的影响; 若无法进行规避, 则必须在该中断中查询更高优先级中断的状态并执行。
例如在 DSP 平台中, 使用 CY 7 C 68001 USB 芯片, 在 USB 端点 8 传输中断中, 需要在中断中向 USBFIFO 写入 512 个字节, 用时较长, 将会影响扫描中断的执行, 造成扫描行周期变化, 影响扫描图像质量; 因此可以考虑每写入 FIFO 128 个字节查询一次扫描中断的状态, 若扫描中断状态置位, 则执行扫描中断处理函数, 减小对扫描行周期的影响。



中断向量表建议放置在 RAM 区, 以便于动态更改中断服务程序
在 ARM 异常中断中, 异常复位时对当前的程序状态进行记录, 以便查找问题。
